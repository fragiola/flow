---
title: Nodes and edges
description: A flow is one JSON document of nodes and edges, with ids, positions, data and permission flags, which the model keeps valid through every command.
---

A flow's whole state is one document, `{ version: 1, nodes, edges }`: plain JSON, frozen, checked
against its JSON Schema when the model loads it. A **node** is a box at a position, of a type of
yours, holding your data. An **edge** joins a source node to a target node, optionally at given
handles, and is drawn as a path of its type. The viewport is not in the document: it is view state
([The viewport](/docs/concepts/viewport)).

## A node

```ts
const node: FlowNodeInput<Types> = {
    id: "fetch",                    // optional on input: generated when missing
    type: "task",                   // a node type of your registry
    position: { x: 120, y: 80 },    // its top-left corner (the root's nodeOrigin), in flow coordinates
    data: { title: "Fetch orders", done: false },
    width: 180,                     // optional: the size the document gives
    height: 64,
    zIndex: 1,                      // optional: drawn above the nodes with less (default 0)
    draggable: true,                // flags, each with its default
    selectable: true,
    connectable: true,
    deletable: true,
    hidden: false,
};
```

Flow coordinates have x growing to the right and y growing down. A node without `width` and
`height` takes the size of what you render in it, measured by the engine. With `subflows()`, a
node may live in a `parentId`, its position then relative to its parent
([Sub-flows](/docs/guides/sub-flows)); with `selection()`, it may be `selected`.

## An edge

```ts
const edge: FlowEdgeInput<Types> = {
    id: "fetch-parse",              // optional on input
    source: "fetch",                // the node it starts at
    target: "parse",                // the node it ends at
    sourceHandle: "out",            // optional: the source node's handle
    targetHandle: "in",             // optional: the target node's handle
    type: "smoothstep",             // bezier (default), smoothstep, step, straight, or your own
    data: { weight: 1 },            // optional
    zIndex: 1,                      // optional: drawn above the edges with less (default 0)
    selectable: true,
    deletable: true,
    hidden: false,
    reconnectable: true,
};
```

An edge without a handle uses its node's first handle of that type (a source handle at its
source, a target handle at its target), or, when the node has none, leaves the source by its
bottom and enters the target by its top. An edge of a type of yours gets the bezier path, and its
ends to draw your own ([Custom edges](/docs/guides/custom-edges)).

## Where a node may go

With `subflows()`, a node's `extent` bounds it: `"parent"` keeps it inside its parent, a flow
rectangle `{ x, y, width, height }` inside that rectangle (in its position's coordinates, so
relative to its parent's top-left corner for a child). The root's `nodeExtent` bounds every node
at once. Drags, the arrow keys and resizes keep a node's whole box inside every bound it has; a
node larger than its bounds keeps to their top-left corner.

```ts
const nodes: FlowNodeInput<Types>[] = [
    // with subflows(): this node stays inside a 400 × 300 area
    { id: "note", type: "note", position: { x: 20, y: 20 }, extent: { x: 0, y: 0, width: 400, height: 300 }, data: { text: "" } },
];
```

</Framework>

The model itself keeps only `"parent"` (with the sizes the document gives): a rectangle is kept by
the gestures, so `node.move` from your code may place a node outside it.

## Which is drawn above

Nodes are drawn in the order of their `zIndex` (default 0), then of the document; a child is
always above its parent. A selected node rises above the others, its children with it, while the
root's `elevateNodesOnSelect` is on (the default). Edges are ordered among themselves the same way,
and a selected edge rises above the other edges with `elevateEdgesOnSelect` (off by default).
Change an order from code with two commands, `null` putting the default back:

```ts
model.run("node.set-z-index", { nodeId: "note", zIndex: 10 });
model.run("edge.set-z-index", { edgeId: "fetch-parse", zIndex: null });
```

<Framework name="react">

```tsx
<Flow.Root defaultNodes={nodes} defaultEdges={edges} elevateNodesOnSelect={false} elevateEdgesOnSelect>
    …
</Flow.Root>
```

</Framework>

```vue
    …
```


</Framework>

The order holds within each layer: edges are always drawn below every node, whatever their
`zIndex` ([Limitations](/docs/limitations)). The adapters put a node's order in its structural
`z-index` (a selected node's is raised by 10 000), so a `z-index` of yours on a node is
overridden; the first render, before the engine is attached, has none.

## The rules the model keeps

- **Ids are unique**, among nodes and among edges. A node or an edge added without an id gets one
  from `createId(kind)` (an option of `createFlowModel` and of the root), by default
  `node-1`, `edge-1`, … The model never uses a global `crypto`.
- **Edges join existing, connectable nodes.** `edge.add` refuses a missing node, a node with
  `connectable: false`, and a second edge joining the same handles in the same direction. A self
  loop is allowed; forbid it in a middleware if your flow does not want it
  ([Connection rules](/docs/guides/connection-rules)).
- **An edge never dangles.** Removing a node removes its edges in the same step (and, with
  `subflows()`, its children), whatever the edges' own `deletable`.
- **Flags hold for code too.** `draggable: false` refuses `node.move` from a drag and from your
  code; `deletable: false` refuses `node.remove`; `selectable: false` refuses `selection.set`. Change
  a flag with `node.set-flags` or `edge.set-flags`.
- **A feature's field needs its feature.** `selected` needs `selection()`; `parentId`, `extent` and
  `expandParent` need `subflows()`. A document carrying one without it is refused, with the path of
  each problem.

## Reading nodes and edges

```ts
model.get("node-by", { id: "fetch" });                              // a node, or undefined
model.get("all-nodes");                                             // every node, in drawing order
model.get("node-edges-by", { nodeId: "fetch", handleType: "source" }); // the edges that start there
model.get("connected-edges-by", { nodeIds: ["fetch", "parse"] });   // the edges touching either
model.get("absolute-position-by", { nodeId: "fetch" });             // with its parents' positions added
model.is("node-deletable", { nodeId: "fetch" });
```

In a component under the root, `useNodes()` and `useEdges()` re-render on every change, and
`useSelection()` when the selection changes (in Vue, computed refs that change then; in Svelte,
their `current`; in Angular, signals) ([Hooks](/docs/api/primitives/hooks)).

## Controlled or not

The root creates its model from `defaultNodes` and `defaultEdges`, read once. Or control them:
give `nodes` and `edges` with `onNodesChange` and `onEdgesChange`, and the root brings the model
to your lists with the commands a user would have run, so middleware and listeners still see
every change.

<Framework name="react">

```tsx
const [nodes, setNodes] = useState<readonly FlowNode<Types>[]>(initialNodes);

<Flow.Root<Types, typeof features>
    features={features}
    nodes={nodes}
    onNodesChange={setNodes}
    defaultEdges={edges}
>
    …
</Flow.Root>;
```

</Framework>

<Framework name="vue">

```vue
<script setup lang="ts">
import type { FlowNode } from "@fragiola/flow-vue";
import { shallowRef } from "vue";

// the model's lists are frozen: a shallowRef keeps them as they are
const nodes = shallowRef<readonly FlowNode<Types>[]>(initialNodes);
</script>

<template>
    <Flow.Root :features="features" v-model:nodes="nodes" :default-edges="edges">…</Flow.Root>
</template>
```

In Vue, `nodes` + `onNodesChange` is `v-model:nodes` (and `v-model:edges`): the root emits
`update:nodes` with the model's list after every change, and each node's slot is its own
component, so a new list re-renders the nodes that changed only.

</Framework>

<Framework name="svelte">

```svelte
<script lang="ts">
    import type { FlowNode } from "@fragiola/flow-svelte";

    // the model's lists are frozen: $state.raw keeps them as they are
    let nodes = $state.raw<readonly FlowNode<Types>[]>(initialNodes);
</script>

<Flow.Root {features} bind:nodes defaultEdges={edges}>…</Flow.Root>
```

In Svelte, `nodes` + `onNodesChange` is `bind:nodes` (and `bind:edges`), or `nodes` with
`onnodeschange`: the root writes the model's list back after every change. Assign a new list
(`nodes = [...nodes, node]`): a list mutated in place (`push`) keeps its identity and is not
synced, as in React.

</Framework>

<Framework name="angular">

```ts
import { Component, signal } from "@angular/core";
import { FLOW, type FlowNode } from "@fragiola/flow-angular";

@Component({
    selector: "app-controlled",
    imports: [FLOW],
    template: `<div flowRoot [features]="features" [(nodes)]="nodes" [defaultEdges]="edges">…</div>`,
})
export class Controlled {
    protected readonly features = features;
    protected readonly edges = edges;
    // the model's lists are frozen: a signal holds them as they are
    protected readonly nodes = signal<readonly FlowNode<Types>[]>(initialNodes);
}
```

In Angular, `nodes` + `onNodesChange` is `[(nodes)]` (and `[(edges)]`), or `[nodes]` with
`(nodesChange)`: the root emits the model's list after every change. Set a new list
(`nodes.set([...nodes(), node])`). A bound output checks your component's whole template on every
emit (each drag step): bind it where you need the list, and read it with `injectNodes()` or the
flow ref otherwise.

</Framework>

Controlled nodes need every id. In React, keep the children functions stable when the app re-renders on each
change (a module function, `useCallback`), or every node re-renders.
