---
title: The primitive contract
description: The rules every Flow part follows, from render instead of asChild to state-aware className and style, merged refs, forwarded props and no text.
---

Every primitive of `@fragiola/flow-react` and `@fragiola/flow-vue` follows the same rules, shared with every Fragiola
library, so learning one part teaches the others. The adapter's tests enforce each one.

## `render`, never `asChild`

A part renders one element by default. `render` replaces it: an element, whose props are merged
with the part's, or a function of the props and the part's state, which must spread the props.

<Framework name="react">

```tsx
<Flow.Node<Types> node={node} render={<li />} />

<Flow.Edge<Types> edge={edge} render={(props, state) => <g {...props} opacity={state.reconnecting ? 0.4 : 1} />} />
```

</Framework>

<Framework name="vue">

```vue
<Flow.Node :node="node" as="li" />

<Flow.Edge :edge="edge">
    <template #render="{ props, state, children }">
        <g v-bind="props" :opacity="state.reconnecting ? 0.4 : 1">
            <component :is="children" />
        </g>
    </template>
</Flow.Edge>
```

In Vue, `render={<li />}` is `as` (a tag or a component, the part's props merged into it), and
a render function is the `render` scoped slot, `{ props, state, children }`: `v-bind="props"`
carries the template ref, the attributes and the structural style, and `children` is the part's
content.

</Framework>

<Framework name="svelte">

```svelte
<Flow.Node {node}>
    {#snippet render({ props, children })}<li {...props}>{@render children()}</li>{/snippet}
</Flow.Node>

<Flow.Edge {edge}>
    {#snippet render({ props, state, children })}
        <g {...props} opacity={state.reconnecting ? 0.4 : 1}>
            {@render children()}
        </g>
    {/snippet}
</Flow.Edge>
```

In Svelte, both forms of `render` are the `render` snippet, `{ props, state, children }`:
`{...props}` carries the attributes, the handlers, the structural style and the attachment that
registers the element, and `children` is the part's content.

</Framework>

<Framework name="angular">

```html
<li [flowNode]="node">{{ node.data.label }}</li>

<svg:g [flowEdge]="edge" #e="flowEdge" [attr.opacity]="e.state()?.reconnecting ? 0.4 : 1">
    <svg:path flowEdgePath />
</svg:g>
```

In Angular there is no `render`: the directive goes on your own element, which keeps every
attribute and binding you write, and gets the part's attributes, structural style and
registration. A part's state is its `state()` signal, through its `exportAs` (`#e="flowEdge"`).

</Framework>

`props.ref` is a callback ref, so it fits any element: `render={(props) => <section {...props} />}`
needs no cast. The props carry what the engine depends on: the ref that registers a node or a
handle, `data-flow-part` and `data-flow-id`, the state attributes and the structural style.

## `className` and `style`: a value or a function

In React, both take a value, or a function of the part's state:

<Framework name="react">

```tsx
<Flow.Node<Types>
    node={node}
    className={(state) => (state.selected ? "node node-selected" : "node")}
    style={(state) => ({ opacity: state.dragging ? 0.8 : 1 })}
/>
```

</Framework>

<Framework name="vue">

```vue
<Flow.Node :node="node" class="node data-selected:ring-2 data-dragging:opacity-80" v-slot="{ state }">
    {{ node.data.label }}
    <span v-if="state.selected">(selected)</span>
</Flow.Node>
```

In Vue, `class` and `style` take Vue's own forms (a string, an array, an object), never a function:
Vue normalizes both before a component sees them. A part's state reaches the template through its
`data-*` attributes (`data-selected:ring-2`), its default slot (`{ state }`) and its `render`
slot.

</Framework>

<Framework name="svelte">

```svelte
<Flow.Node {node} class={(state) => ["node data-selected:ring-2", state.dragging && "opacity-80"]}>
    {#snippet children({ state })}
        {node.data.label}
        {#if state.selected}<span>(selected)</span>{/if}
    {/snippet}
</Flow.Node>
```

In Svelte, `class` (any of Svelte's forms: a string, an array, an object) and `style` (a CSS
string or a record) take a value or a function of the state, as in React. A part's state also
reaches the template through its `data-*` attributes, its `children` snippet (`{ state }`) and
its `render` snippet.

</Framework>

<Framework name="angular">

```html
<div [flowNode]="node" #n="flowNode" class="node data-selected:ring-2" [class.opacity-80]="n.state()?.dragging">
    {{ node.data.label }}
    @if (n.state()?.selected) {
        <span>(selected)</span>
    }
</div>
```

In Angular, `className` and `style` functions of the state are your own `[class.x]` and
`[style.x]` bindings over the part's `state()`; the `data-*` attributes carry the state too.

</Framework>

Each part's state is listed on its API page (`NodeState`, `HandleState`, `EdgeState`, …). For a
style that only follows state, prefer the `data-*` attributes from a stylesheet: the same CSS then
works for every framework's adapter ([State attributes](/docs/concepts/state-attributes)).

## Inline style is structural only

A part writes only what places it: a node's `position: absolute` and `transform: translate(x, y)`
(with the document's `width` and `height` when given), the layers' absolute boxes, a label's or a
toolbar's anchor, the root's `position: relative; overflow: hidden`. The engine writes the
viewport's `transform` itself, never the framework. Your `style` is merged under the structural keys, so
they always keep the part's value.

Two placements are defaults your style may override: where a `Flow.Handle` sits on its side
(centred), so several handles can share one side, and an SVG part's presentation defaults
(`fill="none"` on paths, `currentColor` for the background's marks).

<Framework name="react">

```tsx
<Flow.Handle type="source" side="right" handleId="yes" style={{ top: "30%" }} />
<Flow.Handle type="source" side="right" handleId="no" style={{ top: "70%" }} />
```

</Framework>

<Framework name="vue">

```vue
<Flow.Handle type="source" side="right" handle-id="yes" :style="{ top: '30%' }" />
<Flow.Handle type="source" side="right" handle-id="no" :style="{ top: '70%' }" />
```

</Framework>

<Framework name="svelte">

```svelte
<Flow.Handle type="source" side="right" handleId="yes" style="top: 30%" />
<Flow.Handle type="source" side="right" handleId="no" style={{ top: "70%" }} />
```

</Framework>

<Framework name="angular">

```html
<div flowHandle type="source" side="right" handleId="yes" style="top: 30%"></div>
<div flowHandle type="source" side="right" handleId="no" [style.top]="'70%'"></div>
```

</Framework>

## `ref` is a plain prop

In React, `ref` is merged with the part's own callback ref, so yours receives the element too:

<Framework name="react">

```tsx
const nodeRef = useRef<HTMLDivElement>(null);
<Flow.Node<Types> node={node} ref={nodeRef} />;
```

</Framework>

<Framework name="vue">

```vue
<script setup lang="ts">
import { ref } from "vue";

// the component: its `$el` is the node's element
const nodeRef = ref<{ $el: HTMLElement } | null>(null);
</script>

<template>
    <Flow.Node ref="nodeRef" :node="node" />
</template>
```

In Vue a template `ref` on a part is the component, as for any component; its `$el` is the
element. `EdgeLabel` and `NodeToolbar` render their element elsewhere: reach it through the
`render` slot.

</Framework>

<Framework name="svelte">

```svelte
<script lang="ts">
    // the node's element once mounted, null after
    let element = $state<HTMLDivElement | null>();
</script>

<Flow.Node bind:ref={element} {node} />
<!-- or an attachment, which runs on the element (the render snippet's one too) -->
<Flow.Node {node} {@attach (element) => console.log(element)} />
```

In Svelte, `bind:ref` is the element (`undefined` until mounted, `null` after), and an
attachment on a part reaches its element. `EdgeLabel` and `NodeToolbar` mount their element
elsewhere; both reach it there.

</Framework>

<Framework name="angular">

```ts
import { Component, type ElementRef, viewChild } from "@angular/core";
import { FLOW, type FlowNode, type FlowNodeDirective } from "@fragiola/flow-angular";

@Component({
    selector: "app-node-ref",
    imports: [FLOW],
    template: `<div [flowNode]="node" #element #part="flowNode"></div>`,
})
export class NodeRef {
    node!: FlowNode;
    // the element is yours: a template reference, or viewChild
    readonly element = viewChild<ElementRef<HTMLDivElement>>("element");
    // the directive, through its exportAs: its state() signal
    readonly part = viewChild<FlowNodeDirective>("part");
}
```

In Angular the element is your own, so `ref` is a template reference (`#element`) or
`viewChild`; `#part="flowNode"` reaches the directive. An edge label and a toolbar move their
element (into the edges' HTML layer, into the root): a reference still reaches it there.

</Framework>

## Props are forwarded, handlers composed

Every prop a part does not know goes to its element: `aria-*`, `data-*`, `title`, `role`,
`tabIndex`, event handlers (in Vue, every fallthrough attribute and
listener; in Svelte, every attribute and `on…` handler prop; in Angular, the element is yours). A handler you pass
runs after the part's own. Gestures are not the framework's handlers: the engine listens on the root and resolves every press from the part attributes, so a
field, a button or a link inside a node starts no drag, and neither does an element marked
`data-flow-no-gesture`.

## State through `data-*` only

A part never adds a class name. Its state is `data-*` (present as `""` or absent, never
`"false"`), plus `aria-pressed` and `disabled` on the buttons that have them.

## No text, no names

The parts render only your children and set no `aria-label` and no role. Every name and every
announcement comes from you: see [Accessible names](/docs/getting-started/accessible-names).
