---
title: Custom nodes
description: Render each node type from its own typed data, give it handles where you want them, edit its data from inside, and add new nodes from a palette.
---

There is no node component to configure and no `nodeTypes` map. `Flow.Nodes` calls your children
function once per node, and you render whatever that node should be: a card, a form, a shape, a
preview. The package places the element at the node's position, measures it, and resolves presses
on it. What the node looks like, what it shows and what its fields do are yours.

<Example id="custom-nodes" />

## One function for every node type

Name your node types and their data in a `Types` registry: `node.type` then narrows `node.data`,
so each branch of the function reads the fields of its own type.

<Framework name="react">

```tsx title="custom-nodes.tsx"
import { Flow, type FlowNode, type FlowTypes } from "@fragiola/flow-react";

interface Types extends FlowTypes {
    readonly nodes: {
        colour: { label: string; colour: string };
        number: { label: string; value: number };
        preview: { label: string };
    };
}

type Node = FlowNode<Types>;

/** One function for every node: stable, so a change re-renders only the node it touched. */
function renderNode(node: Node) {
    return (
        <Flow.Node<Types> node={node} className="node">
            {node.type === "colour" && <ColourNode node={node} />}
            {node.type === "number" && <NumberNode node={node} />}
            {node.type === "preview" && <PreviewNode node={node} />}
        </Flow.Node>
    );
}

// inside the root:
// <Flow.Nodes<Types>>{renderNode}</Flow.Nodes>
```

Keep the function stable (a module function, or `useCallback`): `Flow.Nodes` memoizes each node's
rendering on the node and the function, so a drag step re-renders only the nodes it moved. A new
function on every render re-renders every node.

</Framework>

and `node.type` narrows `node.data` in the template too. Each node's slot renders in a component
of its own whose props are the node: a drag step re-renders only the nodes it moved, whatever
the slot holds.

</Framework>


In Angular, the children function is the `flowNodesItem` template, typed by the model
(`[flowNodesItem]="model"`), and `@if` on `node.type` narrows `node.data` in the template too.
Each node's view is its own (checked on its own): a drag step checks again only the nodes it
moved, whatever the template holds.

</Framework>

## A component per type

Each branch is an ordinary component. `Extract` gives it the node of its own type, and
[`useFlow`](/docs/api/primitives/hooks) gives it the model to change its data with
`node.set-data`, a shallow merge:

<Framework name="react">

```tsx
import { Flow, type FlowNode, type FlowTypes, useFlow } from "@fragiola/flow-react";
import { connection } from "@fragiola/flow-react/connection";
import { drag } from "@fragiola/flow-react/drag";
import { selection } from "@fragiola/flow-react/selection";

const features = [selection(), drag(), connection()] as const;

function ColourNode({ node }: { node: Extract<FlowNode<Types>, { type: "colour" }> }) {
    const { model } = useFlow<Types, typeof features>();
    return (
        <>
            <label>
                <span>{node.data.label}</span>
                <input
                    type="color"
                    value={node.data.colour}
                    onChange={(event) =>
                        model.run("node.set-data", {
                            nodeId: node.id,
                            data: { colour: event.target.value },
                        })
                    }
                />
            </label>
            <Flow.Handle type="source" side="right" className="handle" />
        </>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="colour-node.vue"
<script setup lang="ts">
```

```ts title="colour-node.ts"
import { Component, input } from "@angular/core";
import { FLOW, type FlowNode, injectFlow } from "@fragiola/flow-angular";
import { connection } from "@fragiola/flow-angular/connection";
import { drag } from "@fragiola/flow-angular/drag";
import { selection } from "@fragiola/flow-angular/selection";

// rendered inside [flowNode]: its handle finds the node through it
@Component({

    imports: [FLOW],
    template: `
        <label>
            <span>{{ node().data.label }}</span>
            <input type="color" [value]="node().data.colour" (input)="pick($event)" />
        </label>
        <div flowHandle type="source" side="right" class="handle"></div>

})
export class ColourNode {

    private readonly flow = injectFlow<Types, typeof features>();

    protected pick(event: Event): void {

        this.flow.model().run("node.set-data", { nodeId: this.node().id, data: { colour } });
    }
}
```

</Framework>

A press on a field, a button or a link inside a node starts no gesture: typing in the input never
drags the node. Mark anything else that must keep its presses with `data-flow-no-gesture`, and an
element that scrolls with `data-flow-no-wheel` (the wheel then scrolls it instead of zooming).

## Drag by a handle

A node that holds an element with `data-flow-drag-handle` drags only from that element: a title
bar, a grip. A press anywhere else on the node selects it but moves nothing and does not pan, so
its body is free for a canvas, a chart or text to select. The `custom-nodes` example's preview
drags by its title bar. `DRAG_HANDLE_ATTRIBUTE` is the attribute's name, for code that builds it.

<Framework name="react">

```tsx
<Flow.Node<Types> node={node} className="node">
    <div data-flow-drag-handle="" className="cursor-grab border-b px-2 py-1 active:cursor-grabbing">
        {node.data.label}
    </div>
    <div className="p-2">…</div>
</Flow.Node>
```

</Framework>

<Framework name="vue">


</Framework>

not limit its parent.
Keyboard moves (the arrows) and code (`node.move`) ignore it.

## Where a node stands

A node's `position` is its box's top-left corner. The root's `nodeOrigin` moves that anchor, as
shares of the node's size: `{ x: 0.5, y: 0.5 }` stands every node on its centre, which suits a
layout that computes centres (a circle, a force layout). The engine applies it everywhere a box
is drawn or measured (edges, handles, the minimap, `fit-view`, the selection box, drags and
resizes); a child of a sub-flow keeps its top-left corner inside its parent.

<Framework name="react">

```tsx
<Flow.Root defaultNodes={nodes} nodeOrigin={{ x: 0.5, y: 0.5 }} className="h-96">
    …
</Flow.Root>
```

</Framework>

<Framework name="vue">

```vue
<Flow.Root :default-nodes="nodes" :node-origin="{ x: 0.5, y: 0.5 }" class="h-96">…</Flow.Root>
```

</Framework>

<Framework name="svelte">

```svelte
<Flow.Root defaultNodes={nodes} nodeOrigin={{ x: 0.5, y: 0.5 }} class="h-96">…</Flow.Root>
```

</Framework>

<Framework name="angular">

```html
<div flowRoot [defaultNodes]="nodes" [nodeOrigin]="{ x: 0.5, y: 0.5 }" class="h-96">…</div>
```

</Framework>

The first render, before the engine measures anything (and a server render), places nodes by
their top-left corner: an origin applies from the next frame.

## Read what is wired into a node

A node that shows its inputs reads the edges and the nodes with
[`useEdges` and `useNodes`](/docs/api/primitives/hooks), which re-render it when they change:

<Framework name="react">

```tsx
import { useEdges, useNodes } from "@fragiola/flow-react";

/** The node wired into one of `nodeId`'s target handles, if any. */
function useInput(nodeId: string, handleId: string) {
    const edges = useEdges<Types>();
    const nodes = useNodes<Types>();
    const edge = edges.find((e) => e.target === nodeId && e.targetHandle === handleId);
    return nodes.find((n) => n.id === edge?.source);
}
```

</Framework>

<Framework name="vue">

```ts title="use-input.ts"
import { useEdges, useNodes } from "@fragiola/flow-vue";
import { computed } from "vue";

/** The node wired into one of `nodeId`'s target handles, if any. */
export function useInput(nodeId: string, handleId: string) {
    const edges = useEdges<Types>();
    const nodes = useNodes<Types>();
    return computed(() => {
        const edge = edges.value.find((e) => e.target === nodeId && e.targetHandle === handleId);
        return nodes.value.find((n) => n.id === edge?.source);
    });
}
```

In Vue, `useEdges` and `useNodes` are computed refs: derive from them with `computed`.

</Framework>

<Framework name="svelte">

```ts title="use-input.svelte.ts"
import { useEdges, useNodes } from "@fragiola/flow-svelte";

/** The node wired into one of `nodeId`'s target handles, if any. */
export function useInput(nodeId: string, handleId: string) {
    const edges = useEdges<Types>();
    const nodes = useNodes<Types>();
    const input = $derived.by(() => {
        const edge = edges.current.find((e) => e.target === nodeId && e.targetHandle === handleId);
        return nodes.current.find((n) => n.id === edge?.source);
    });
    return {
        get current() {
            return input;
        },
    };
}
```

In Svelte, `useEdges` and `useNodes` give `{ current }`: derive from them with `$derived`, in a
`.svelte.ts` module (a rune needs the suffix), and call your rune in a component's script.

</Framework>

<Framework name="angular">

```ts title="inject-input.ts"
import { computed, type Signal } from "@angular/core";
import { type FlowNode, injectEdges, injectNodes } from "@fragiola/flow-angular";

/** The node wired into one of `nodeId`'s target handles, if any. */
export function injectInput(nodeId: () => string, handleId: string): Signal<FlowNode<Types> | undefined> {
    const edges = injectEdges<Types>();
    const nodes = injectNodes<Types>();
    return computed(() => {
        const edge = edges().find((e) => e.target === nodeId() && e.targetHandle === handleId);
        return nodes().find((n) => n.id === edge?.source);
    });
}
```

In Angular, `injectEdges` and `injectNodes` return signals: derive from them with `computed`, in
a function you call in an injection context (a field of a component inside the root).

</Framework>

For a large flow, read only what you need with `model.get("node-edges-by", { nodeId, handleType:
"target" })` in a `model.subscribe` listener instead: `useNodes` re-renders on every change of any
node.

When the handle does not matter, ask for the nodes at the other end of a node's edges directly:
`incomers-by` gives the nodes its incoming edges come from, `outgoers-by` the nodes its outgoing
edges go to, each node once, in the document's order (a self loop makes a node its own incomer and
outgoer):

```ts
const upstream = model.get("incomers-by", { nodeId: "review" }); // FlowNode<Types>[]
const downstream = model.get("outgoers-by", { nodeId: "review" });
const isFirstStep = upstream.length === 0; // nothing comes into it
```

## Nodes that overlap

The engine knows every node's box on the flow (its measured or given size, the root's
`nodeOrigin`, a child inside its parent), so it answers which nodes overlap one, or a rectangle of
yours: `intersecting-nodes` with a `nodeId` (that node is left out) or a `rect` in flow
coordinates, and `partial: false` for only the nodes wholly inside. A drop on another node, say:

```ts
engine.subscribe((event) => {
    if (event.type !== "nodes-move" || event.nodeIds.length !== 1) return;
    const [nodeId] = event.nodeIds;
    const [target] = engine.get("intersecting-nodes", { nodeId });
    if (target) model.run("edge.add", { source: target.id, target: nodeId });
});
```

Hidden nodes and nodes not measured yet are never in the answer. A parent and its children
overlap; filter on `parentId` when that is not what you mean.

## Add nodes from a palette

<Example id="add-nodes" />

A palette outside the root reaches the flow through a [flow ref](/docs/api/primitives/flow-ref).
The browser's own drag and drop carries the node type; on the drop,
`engine.get("screen-to-flow", { x, y })` turns the drop's client point into flow coordinates, and
`node.add` puts the node there:

<Framework name="react">

```tsx title="add-nodes.tsx"
import { Flow, type FlowTypes, useFlowRef } from "@fragiola/flow-react";
import type { DragEvent } from "react";

type Shape = "circle" | "square" | "diamond";

interface Types extends FlowTypes {
    readonly nodes: { shape: { shape: Shape; label: string } };
}

const MIME = "application/x-flow-shape";

export function Editor() {
    const flow = useFlowRef<Types, typeof features>();

    function onDrop(event: DragEvent<HTMLDivElement>) {
        const shape = event.dataTransfer.getData(MIME) as Shape;
        const current = flow.current;
        if (!shape || !current) return;
        event.preventDefault();
        const point = current.engine.get("screen-to-flow", { x: event.clientX, y: event.clientY });
        current.model.run("node.add", {
            type: "shape",
            // the node's top-left corner, so that its middle lands on the point
            position: { x: point.x - 50, y: point.y - 20 },
            data: { shape, label: shape },
        });
    }

    return (
        <div className="layout">
            <button
                type="button"
                draggable
                onDragStart={(event) => event.dataTransfer.setData(MIME, "square")}
            >
                Task
            </button>
            <Flow.Root<Types, typeof features>
                features={features}
                flowRef={flow}
                onDragOver={(event) => {
                    if (!event.dataTransfer.types.includes(MIME)) return;
                    event.preventDefault();
                }}
                onDrop={onDrop}
                className="flow"
            >
                {/* the viewport, edges and nodes */}
            </Flow.Root>
        </div>
    );
}
```

</Framework>

```svelte title="add-nodes.svelte"
    <Flow.Root {features} flowRef={flow} class="flow" {ondragover} {ondrop}>
        <!-- the viewport, edges and nodes -->
    </Flow.Root>
</div>
```

In Svelte, `flowRef={flow}` and `flow.current` are React's; the root's element takes your
handlers (`ondragover`, `ondrop`) as it takes any attribute.

</Framework>

<Framework name="angular">

```ts title="add-nodes.ts"
import { Component } from "@angular/core";
import { createFlowRef, FLOW, type FlowTypes } from "@fragiola/flow-angular";

type Shape = "circle" | "square" | "diamond";

interface Types extends FlowTypes {
    readonly nodes: { shape: { shape: Shape; label: string } };
}

const MIME = "application/x-flow-shape";

@Component({
    selector: "app-add-nodes",
    imports: [FLOW],
    template: `
        <div class="layout">
            <button type="button" draggable="true" (dragstart)="$event.dataTransfer?.setData(mime, 'square')">
                Task
            </button>
            <div flowRoot [features]="features" [flowRef]="flow" class="flow" (dragover)="over($event)" (drop)="drop($event)">
                <!-- the viewport, edges and nodes -->
            </div>
        </div>
    `,
})
export class AddNodes {
    protected readonly mime = MIME;
    protected readonly features = features;
    protected readonly flow = createFlowRef<Types, typeof features>();

    protected over(event: DragEvent): void {
        if (event.dataTransfer?.types.includes(MIME)) event.preventDefault();
    }

    protected drop(event: DragEvent): void {
        const shape = event.dataTransfer?.getData(MIME) as Shape | undefined;
        const current = this.flow.current;
        if (!shape || !current) return;
        event.preventDefault();
        const point = current.engine.get("screen-to-flow", { x: event.clientX, y: event.clientY });
        current.model.run("node.add", {
            type: "shape",
            // the node's top-left corner, so that its middle lands on the point
            position: { x: point.x - 50, y: point.y - 20 },
            data: { shape, label: shape },
        });
    }
}
```

In Angular, the root's element is yours: `(dragover)` and `(drop)` are listeners on it like on any
element, and `[flowRef]="flow"`, `flow.current` are React's flow ref.

</Framework>

`node.add` generates the id when you leave it out (the model's `createId`). A node added without a
`width` and `height` is measured once rendered, and its edges are drawn from then on.

## What stays yours

- The look of every node type, its content and its fields.
- Where handles sit and what they look like (`data-valid`, `data-invalid` while a connection
  hovers them).
- The node's name for assistive technology: see
  [Accessible names](/docs/getting-started/accessible-names).
