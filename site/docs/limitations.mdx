title: Limitations
description: What xyflow has that this package does not, why, and what to do instead, plus the known gaps of the current release.
---

The behaviour reference of this package is [xyflow](https://github.com/xyflow/xyflow) (React
Flow): its gestures, its edge cases and its tests were studied, and none of its code was copied.
This page lists, honestly, what it has that this package does not, all of it on purpose (app
policy, cosmetics, or a choice of the model), each with what to do instead, and the known gaps
of the current release. No gap is left open: where this package still behaves differently from
React Flow (its z-order defaults among them), it does so on purpose and is listed below, so there
is no "not yet" list. Found something missing from this page? [Open an issue](https://github.com/fragiola/flow/issues).

## On purpose

| xyflow | here | why, and what to do instead |
| --- | --- | --- |
| **`nodeTypes` and `edgeTypes`** maps of components. | A children function on `Flow.Nodes` and `Flow.Edges`. | You render every node and edge, so a `switch` on `node.type` is your registry, typed by your own `Types` (see [Custom nodes](/docs/guides/custom-nodes)). |
| **`isValidConnection`**. | Connection rules are middleware on the model. | One rule for every edge, from a drag or from code: `model.use` vetoes `edge.add`, and the drag shows `data-invalid` before the drop (see [Connection rules](/docs/guides/connection-rules)). `onConnect`, `onConnectStart` and the other gesture callbacks are the root's ([Root](/docs/api/primitives/root#props)). |
| **`nodesDraggable`, `nodesConnectable`, `elementsSelectable`, `edgesReconnectable`** props. | `engine.run("set-interactive", { drag, connect, select, reconnect })`, engine state the lock button switches (`drag`, `connect` and `select`; moving an edge's end needs `connect` too); the document's flags per node and edge. | One switch per kind at run time, read by every gesture when it acts: run it from your own toggle, or use `Flow.ToggleInteractive`. The root's `interactive` prop switches them all. |
| **`onConnectEnd`** called after every connection. | `onConnect` after an edge was added, `onConnectCancel` (with `from`, `to` and the drop point) when none was. | Handle both: `onConnectCancel` is what "drop on the pane makes a node" needs. |
| **`applyNodeChanges`**, change objects and `onNodesChange(changes)`. | Commands, and the model's lists. | `onNodesChange` receives the nodes; a middleware or `model.subscribe` sees every command with its payload. |
| **Edge markers** (`markerEnd`, `MarkerType`). | No marker is built in. | Markers are plain SVG: define a `marker` and point `markerEnd` at it (see [Custom edges](/docs/guides/custom-edges) and the [Edge markers](/examples/edge-markers) example). |
| Default styles (`@xyflow/react/dist/style.css`), the default node and its label. | Structural style only, and no text at all. | Style every part from `data-flow-part` and its state attributes (see [Styling with plain CSS](/docs/guides/styling-css)). |
| `Panel`, `ViewportPortal`, `EdgeLabelRenderer`. | Put your own elements inside `Flow.Root` (screen pixels) or `Flow.Viewport` (flow coordinates); `Flow.EdgeLabel` portals into the edges' HTML layer. | Mark a panel over the canvas `data-flow-no-gesture` (and `data-flow-no-wheel`). |
| Undo, copy and paste, helper lines, auto layout. | None in the package. | App policy: the [undo and redo](/docs/guides/undo-redo) guide has a copyable history; the rest is commands you run. |
| **`zIndexMode` defaults to `"basic"`**, whose `"basic"` already lifts an edge to the z of an end that is a child or selected, and raises a selected edge (`elevateEdgesOnSelect`). | `zIndexMode` defaults to `"auto"`: an edge between a group's children stands above the group, and a selected edge above the nodes it crosses (`elevateEdgesOnSelect` defaults to true in `"auto"`). `"basic"` is this package's order before `"auto"`: every edge below every node, a selected one raised among the edges only. | A choice, so sub-flows and selected edges stay visible. For every edge below every node, set the root's `zIndexMode` to `"basic"`; to keep `"auto"` without raising a selected edge over the nodes, set its `elevateEdgesOnSelect` to `false`: the same two props in React, Vue, Svelte and Angular (see [Z-order](/docs/concepts/nodes-and-edges#z-order)). |
| `useNodesInitialized`, `useUpdateNodeInternals`. | The engine measures every node and handle with a `ResizeObserver`. | `engine.is("node-measured", { nodeId })`; nothing to refresh by hand. |

## Other things to know

- **Angular has no server render**: its directives write to their elements in the browser, so an
  Angular flow draws its declared edges in the browser's first render, not in server HTML. React,
  Vue and Svelte draw them on the server ([Server rendering](/docs/guides/server-rendering)).
- **Edge labels are not in the server HTML**: a `Flow.EdgeLabel` portals into its layer once
  mounted, so labels appear after hydration, while the paths are already there.
- **The server HTML is drawn at the identity viewport** (`{ x: 0, y: 0, zoom: 1 }`): only the
  engine writes the viewport's transform, so `defaultViewport` and `fitView` apply once it is
  attached after mount, and pan or zoom the whole flow then. For a server-rendered flow without
  that move, keep the identity viewport and place the nodes to fit at zoom 1
  ([Server rendering](/docs/guides/server-rendering)).
- **`fitView` on init runs once, on the sizes known then**: a node's `initialWidth` /
  `initialHeight` count until it is measured, and the view is not fitted again when the measured
  sizes differ. Declare sizes close to the rendered ones, or run `fit-view` after `onInit`.
- **An edge that moves to another render level is remounted** in React, Vue and Svelte (its view
  state inside the edge's own components is lost; the engine gives it its focus back), and moved
  in Angular. It happens when it starts or stops standing above some node (selected in
  `zIndexMode: "auto"`, a `zIndex` change).
- **A `z-index` of yours on a node is overridden** by its structural one (its `zIndex`, raised by
  10 000 while selected with `elevateNodesOnSelect`): order nodes with `zIndex` or
  `node.set-z-index`.
- **A node's `extent` rectangle is kept by the gestures**, not by the model: `node.move` from code
  may place a node outside it (`extent: "parent"` is kept by both). With a `nodeOrigin`, or a
  node's own `origin`, other than the top-left corner, the model's own sub-flow rules count a
  node's position as its corner: `absolute-position-by`, `expandParent` (a parent grows around its
  origin), the model's `extent: "parent"` clamp and `node.set-parent` (which keeps a node's place
  as if it were the corner). The engine's boxes apply the origin.
- **A keyboard connection's targets are fixed when it starts**: a handle rendered while it waits
  is not offered, and a rule that changes meanwhile is checked again only by the final `edge.add`.
  It does not scroll its target into view, and a pointer press while it waits only cancels it.
- **An edge's end is moved with a pointer only**: reconnection has no keyboard path. Remove the
  edge and draw it again from the keyboard, or offer a menu that runs `edge.reconnect`.
- **Handles and resize handles take focus only with `keyboard()` and their feature**
  (`connection()`, `resize()`): give them a name (`aria-label`) once they do, or a screen reader
  reads nothing. A default `NodeResizer`'s eight handles cannot be named: once `keyboard()` is
  installed, pass your own `ResizeHandle` children, each with its `aria-label`.
- **A toolbar for several nodes (`nodeIds`) shows while every one of them is selected**: for the
  selection, pass the selected nodes' ids; a node's own toolbar still shows beside it.
- **A reconnect anchor is drawn under its node's handle** while its edge is below the nodes (edges
  come before nodes), so the mouse grabs it beside the handle.
- **On touch, a finger beside a handle lands on the handle** (Chromium's touch adjustment), so an
  edge's end is grabbed on its stroke near the end: give touch apps a wider
  `reconnection({ radius })`.
- **The minimap drag maps through the view box frozen at the press**: a drag that changes the
  flow's bounds does not rescale under the pointer.
- **A smooth step edge between ends facing each other on one line**, with the target behind the
  source, doubles back on itself.
- **Presses on a node keep their default (focus)**: give nodes `user-select: none`, or a drag
  selects their text.
- **`fit-view`'s own `minZoom` and `maxZoom` narrow the engine's limits**, never widen them.
- **A minimap's `inversePan` and `zoomStep` are one set per root**: they are the engine's minimap
  part options, so several `MiniMap`s on one root share one set: the last to set them wins (they
  cannot pan or zoom differently), and removing one clears them for the others, which fall back to
  `minimap()`'s options. Their taps stay apart: each calls only its own click callback.
- **`useKeyPress` reads every key on its target, typing included**: a combo held in a text field
  counts too. Check `document.activeElement` (or give the hook a `target` of your own) where that
  matters.
- **The selection rectangle shows after a box only by default**: a selection made by modifier
  clicks or `selection.set` has none, unless `selection({ rect: "always" })`.
- **A resize snaps only with `resize({ snap })`**: `drag({ snapGrid })` is the drag's, and a
  resize ignores it.
- **A click is the engine's tap**: a press released within `paneClickDistance` (pane) or
  `nodeClickDistance` (anything else, both 3 px) that started no gesture. A pan that stayed within
  the pane's distance is still a click (its few pixels stay); a click on a handle is not a node's.
  Clicks are told while the flow is locked too (they change nothing).
- **A context menu on one of several selected nodes is the selection's**
  (`onSelectionContextMenu`), not the node's, as is one on the selection rectangle
  (`Flow.NodesSelection`).
- **A resize's steps are the model's transient `node.resize` commands** (`onNodesChange`,
  `model.subscribe`): there is no per-step resize event; `onResizeStart`, `onResizeEnd` and
  `onResizeCancel` frame them.
- **`defaultEdgeOptions` fills `edge.add` only**: the document's own edges (`defaultEdges`, a
  loaded flow) stay as they are, and an edge is not drawn with defaults it does not hold.
- **`beforeDelete` deletes with `node.remove` and `edge.remove`** (one `batch`), not
  `selection.remove`: a middleware watching `selection.remove` does not see those deletes.
- **`onInit` waits for a sized root**: an empty flow whose root had no size when it mounted is not
  ready until a node is measured.
- **The wheel's move ends 150 ms after its last event** (`onMoveEnd`): a wheel has no end of its
  own.
- **jsdom lays nothing out**: in unit tests, stub the sizes (see [Testing your flow](/docs/guides/testing));
  the gestures are tested in a real browser.
