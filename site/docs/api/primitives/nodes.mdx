---
title: Nodes
description: Flow.Nodes is the layer of the nodes, calling your children function once per node that is shown, keyed by id and memoized per node.
---

`Flow.Nodes` goes inside `Flow.Viewport`, after `Flow.Edges`. It calls its children function for
each node that is not hidden, in drawing order, keyed by the node's id (a node keeps its element
when it moves). With the root's `onlyRenderVisible`, only the nodes in view (and those not measured
yet) are rendered (`visible-nodes`). You render each node: usually a `Flow.Node` with its content
and handles, switching on `node.type` when the flow has several.

<Framework name="react">

```tsx
function renderNode(node: FlowNode<Types>) {
    return (
        <Flow.Node<Types> node={node} className="rounded border bg-white p-2">
            {node.data.label}
            <Flow.Handle type="target" side="left" />
            <Flow.Handle type="source" side="right" />
        </Flow.Node>
    );
}

<Flow.Nodes<Types>>{renderNode}</Flow.Nodes>;
```

</Framework>

<Framework name="vue">

```vue
<Flow.Nodes v-slot="{ node }">
    <Flow.Node :node="node" class="rounded border bg-white p-2">
        {{ node.data.label }}
        <Flow.Handle type="target" side="left" />
        <Flow.Handle type="source" side="right" />
    </Flow.Node>
</Flow.Nodes>
```

In Vue, the children function is the default scoped slot, `v-slot="{ node }"`, and each node's
slot is its own component whose props are the node and the slot: a drag step re-renders the
moved nodes only. What else the slot shows follows Vue's reactivity (a ref, a prop it reads); a
template's slot stays the same function, and a new one (a render function's) re-renders every
node.

</Framework>

<Framework name="svelte">

```svelte
<Flow.Nodes>
    {#snippet children(node)}
        <Flow.Node {node} class="rounded border bg-white p-2">
            {node.data.label}
            <Flow.Handle type="target" side="left" />
            <Flow.Handle type="source" side="right" />
        </Flow.Node>
    {/snippet}
</Flow.Nodes>
```

In Svelte, the children function is the `children` snippet, `{#snippet children(node)}`,
rendered in a keyed `{#each}`: a node renders again only when its node object changes (the model
shares the nodes a command did not change), or when a value its snippet reads does, so a drag
step renders the moved nodes only. A new snippet renders every node again, as a new children
function does in React.

</Framework>

<Framework name="angular">

```html
<div flowNodes>
    <ng-template [flowNodesItem]="model" let-node>
        <div [flowNode]="node" class="rounded border bg-white p-2">
            {{ node.data.label }}
            <div flowHandle type="target" side="left"></div>
            <div flowHandle type="source" side="right"></div>
        </div>
    </ng-template>
</div>
```

In Angular, the children function is the item template, `<ng-template flowNodesItem let-node>`
(or `*flowNodesItem="let node"` on the node's element); `[flowNodesItem]="model"` types the node
by the model's registry. Each node's view is its own, checked again only when its node object
changes (the model shares the nodes a command did not change), so a drag step checks the moved
nodes only; whenever your component is checked, every node's view is too, as embedded views are.
Another template (an `@if` around two) renders every node again.

</Framework>

In React, each node's render is memoized on the node and the children function: a drag step
re-renders the moved nodes only. A new children function re-renders every node, so keep it stable (a module
function as above, or `useCallback`) when the app re-renders on each change (controlled `nodes`).

## Props

`NodesProps<T>` extends the [common primitive props](/docs/api/primitives/root#common-props) and
every `div` attribute but `children`.

| prop | type | default | description |
| --- | --- | --- | --- |
| `children` | `(node: FlowNode<T>) => ReactNode` | required | renders one node |

## State

`NodesState`, what `className`, `style` and `render` receive:

| field | type | description |
| --- | --- | --- |
| `count` | `number` | how many nodes are rendered |

## Data attributes

| attribute | value |
| --- | --- |
| `data-flow-part` | `"nodes"` |

## Structural style

`position: absolute` at the viewport's origin. The layer is part of the pane: a press on it, off
any node, pans or draws a selection box.
