---
title: Hooks
description: The hooks read the root's model, engine, view, selection, nodes, edges and keys, select one value or node's data, and render nodes, edges and handles by hand.
---

Every hook reads the enclosing `Flow.Root` (outside one it throws, but `useNodeId` and
`useKeyPress`). Three kinds:

- **Values**: `useFlow`, `useViewport`, `useConnection`, `useSelection`, `useNodes`, `useEdges`.
  Each re-renders its component when its value changes, and only then.
- **Parts**: `useNode`, `useEdge`, `useHandle`, each returning `{ state, props }`: the part's
  state, and the props to spread on your own element (its attributes, the ref that registers it
  with the engine, its structural style). `Flow.Node`, `Flow.Edge` and `Flow.Handle` are built on
  them.
- **Selections**: `useFlowStore`, `useNodeId`, `useNodesData`, `useNodeConnections`,
  `useInternalNode`, `useKeyPress`, `useOnViewportChange`. Each reads one thing and re-renders
  only when it changed (`useOnViewportChange` never: it calls you back).

From outside the root (a toolbar beside it, a test), use a [flow ref](/docs/api/primitives/flow-ref).

In Vue they are composables of the same names, from `@fragiola/flow-vue`: the values are computed
refs (`useViewport().value.zoom`, unwrapped in a template), and a part's `state` and `props` are
computed refs too. Call them in `setup`. [Vue components](/docs/api/primitives/vue) lists their
types. In Svelte they are runes of the same names, from `@fragiola/flow-svelte`: the values are a
`{ current }` that follows the flow (`useViewport().current.zoom`), and a part's `state` and
`props` are getters. Call them in a component's script, inside the root;
[Svelte components](/docs/api/primitives/svelte) lists their types. In Angular they are injection
functions (`injectFlow`, `injectNode`, `injectViewport`, …), from `@fragiola/flow-angular`: the
values are signals, called in an injection context of a component inside the root;
[Angular directives](/docs/api/primitives/angular) lists their types.

## `useFlow`

<Framework name="react">

```tsx
import { useFlow } from "@fragiola/flow-react";

function DeleteSelected() {
    const { model } = useFlow<Types, typeof features>();
    return (
        <button type="button" onClick={() => model.run("selection.remove")}>
            Delete
        </button>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="delete-selected.vue"
<script setup lang="ts">
import { useFlow } from "@fragiola/flow-vue";

const { model } = useFlow<Types, typeof features>();
</script>

<template>
    <button type="button" @click="model.run('selection.remove')">Delete</button>
</template>
```

Call `useFlow` in `setup`: another model remounts the root, so the values never change for a component.

</Framework>

<Framework name="svelte">

```svelte title="delete-selected.svelte"
<script lang="ts">
    import { useFlow } from "@fragiola/flow-svelte";

    const flow = useFlow<Types, typeof features>();
</script>

<button type="button" onclick={() => flow.model.run("selection.remove")}>Delete</button>
```

Call `useFlow` in a component's script, inside the root. `model` and `engine` are getters (another
model given to the root is followed): read them as `flow.model`, not destructured once.

</Framework>

<Framework name="angular">

```ts title="delete-selected.ts"
import { Component } from "@angular/core";
import { injectFlow } from "@fragiola/flow-angular";

// rendered inside [flowRoot]
@Component({
    selector: "app-delete-selected",
    template: `<button type="button" (click)="flow.model().run('selection.remove')">Delete</button>`,
})
export class DeleteSelected {
    protected readonly flow = injectFlow<Types, typeof features>();
}
```

Call `injectFlow` in a field or a constructor of a component inside the root. `model` is a signal
(another model given to the root is followed): read it as `flow.model()`.

</Framework>

`useFlow<T, F>()` returns `UseFlowResult<T, F>`, the model and the engine of the root. Pass the
registry and the features as type arguments: a child cannot infer them through context.

| field | type | description |
| --- | --- | --- |
| `model` | `FlowModel<T, F>` | the flow's document and its rules: `model.run`, `model.get`, `model.is` ([model](/docs/api/model)) |
| `engine` | `FlowEngine<T, F>` | the flow on screen: `engine.run("fit-view")`, `engine.get("viewport")`, `engine.subscribe` ([engine](/docs/api/engine)). There from the first render: before the root is mounted (and on the server) an action is refused and a read is empty |

## `useViewport`

`useViewport()` returns the root's `Viewport` (`{ x, y, zoom }`), re-rendering on every change: a
zoom readout, a control's state. Change it with `engine.run("set-viewport", …)`.

<Framework name="react">

```tsx
function ZoomLevel() {
    const { zoom } = useViewport();
    return <output>{Math.round(zoom * 100)}%</output>;
}
```

</Framework>

<Framework name="vue">

```vue title="zoom-level.vue"
<script setup lang="ts">
import { useViewport } from "@fragiola/flow-vue";

const viewport = useViewport();
</script>

<template>
    <output>{{ Math.round(viewport.zoom * 100) }}%</output>
</template>
```

</Framework>

<Framework name="svelte">

```svelte title="zoom-level.svelte"
<script lang="ts">
    import { useViewport } from "@fragiola/flow-svelte";

    const viewport = useViewport();
</script>

<output>{Math.round(viewport.current.zoom * 100)}%</output>
```

In Svelte, the reading runes (`useViewport`, `useConnection`, `useSelection`, `useNodes`,
`useEdges`) return a `FlowValue` whose `current` follows the flow.

</Framework>

<Framework name="angular">

```ts title="zoom-level.ts"
import { Component } from "@angular/core";
import { injectViewport } from "@fragiola/flow-angular";

@Component({
    selector: "app-zoom-level",
    template: `<output>{{ zoom() }}%</output>`,
})
export class ZoomLevel {
    private readonly viewport = injectViewport();
    protected zoom(): number {
        return Math.round(this.viewport().zoom * 100);
    }
}
```

In Angular, the reading functions (`injectViewport`, `injectConnection`, `injectSelection`,
`injectNodes`, `injectEdges`) return signals that follow the flow.

</Framework>

## `useConnection`

`useConnection()` returns the `Connection` being drawn from a handle (`connection()`), or `null`:
where it starts and ends, the handle it would end at (`to`) and whether the drop would be accepted
(`status`). `Flow.ConnectionLine` uses it.

## `useSelection`

`useSelection<T>()` returns `FlowSelection<T>`, the selected nodes and edges in drawing order
(`selection()`; empty without it), re-rendering when they change.

| field | type | description |
| --- | --- | --- |
| `nodes` | `readonly FlowNode<T>[]` | the selected nodes |
| `edges` | `readonly FlowEdge<T>[]` | the selected edges |

## `useNodes` and `useEdges`

`useNodes<T>()` and `useEdges<T>()` return every node, or every edge, in drawing order (the
model's own frozen list), re-rendering on every change of one: a list beside the flow, a counter.
A drag re-renders them at every step; read `model.get("node-by", { id })` for one entity.

## `useNode`

`useNode<T>(node)` returns `UseNodeResult<T>` for a node rendered by hand: spread `props` on its
element (the engine resolves presses from its attributes).

<Framework name="react">

```tsx
function PlainNode({ node }: { node: FlowNode<Types> }) {
    const { state, props } = useNode(node);
    return (
        <section {...props} aria-label={node.data.label} className={state.selected ? "ring-2" : undefined}>
            {node.data.label}
        </section>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="plain-node.vue"
<script setup lang="ts">
import { type FlowNode, useNode } from "@fragiola/flow-vue";

const props = defineProps<{ node: FlowNode<Types> }>();
const { state, props: element } = useNode(() => props.node);
</script>

<template>
    <section v-bind="element" :aria-label="node.data.label" :class="{ 'ring-2': state.selected }">
        {{ node.data.label }}
    </section>
</template>
```

In Vue, `useNode`, `useEdge` and `useHandle` take a getter or a ref (`() => props.node`) and
return `state` and `props` as computed refs: `v-bind` the props in a template, which unwraps
them. Vue's attribute names are the DOM's: `tabindex` where React writes `tabIndex`.

</Framework>

<Framework name="svelte">

```svelte title="plain-node.svelte"
<script lang="ts">
    import { type FlowNode, useNode } from "@fragiola/flow-svelte";

    let { node }: { node: FlowNode<Types> } = $props();
    const own = useNode(() => node);
</script>

<section {...own.props} aria-label={node.data.label} class={{ "ring-2": own.state.selected }}>
    {node.data.label}
</section>
```

In Svelte, `useNode`, `useEdge` and `useHandle` take the value or a getter (`() => node`, to
follow a prop) and return `state` and `props` as getters: spread `{...own.props}` on your element
(it carries the attachment that registers it with the engine), and do not destructure them.
Svelte's attribute names are the DOM's: `tabindex` where React writes `tabIndex`.

</Framework>

<Framework name="angular">

```ts title="plain-node.ts"
import { Component, input } from "@angular/core";
import { type FlowNode, injectNode } from "@fragiola/flow-angular";

// <section [appPlainNode]="node"></section> inside a flowNodesItem template
@Component({
    selector: "section[appPlainNode]",
    host: {
        "[attr.aria-label]": "node().data.label",
        "[class.ring-2]": "own.state()?.selected",
    },
    template: "{{ node().data.label }}",
})
export class PlainNode {
    readonly node = input.required<FlowNode<Types>>({ alias: "appPlainNode" });
    protected readonly own = injectNode(this.node);
}
```

In Angular, `injectNode`, `injectEdge` and `injectHandle` take the value, a signal or a getter,
bind the host element of the component that calls them (attributes, `tabindex`, structural style,
registration with the engine) and return `state` and `props` as signals.

</Framework>

`state` is `NodeState<T>` (see [`Flow.Node`](/docs/api/primitives/node)):

| field | type | description |
| --- | --- | --- |
| `nodeId` | `string` | its id |
| `node` | `FlowNode<T>` | the node, as the model holds it |
| `x`, `y` | `number` | its top-left corner in absolute flow coordinates |
| `selected` | `boolean` | `data-selected` (`selection()`) |
| `dragging` | `boolean` | `data-dragging` (`drag()`) |
| `resizing` | `boolean` | `data-resizing` (`resize()`) |
| `measured` | `boolean` | its size is known: `data-measured` |
| `focusable` | `boolean` | it takes DOM focus (`keyboard()`) |
| `attributes` | `PartAttributes` | `data-flow-part`, `data-flow-id` and its state |

`UseNodeResult<T>`:

| field | type | description |
| --- | --- | --- |
| `state` | `NodeState<T>` | its state |
| `props` | `{ ref, tabIndex, style } & DataAttributes` | its attributes, `tabIndex` (`0` with `keyboard()`), its structural style (absolute, at its position, with the document's size) and the ref that registers it |

## `useEdge`

`useEdge<T>(edge)` returns `UseEdgeResult<T>` for an edge drawn by hand: spread `props` on an SVG
`g`.

`state` is `EdgeState<T>` (see [`Flow.Edge`](/docs/api/primitives/edge)):

| field | type | description |
| --- | --- | --- |
| `edgeId` | `string` | its id |
| `edge` | `FlowEdge<T>` | the edge, as the model holds it |
| `path` | `EdgePath \| undefined` | its path, label point and ends, once both nodes have a size |
| `selected` | `boolean` | `data-selected` (`selection()`) |
| `reconnecting` | `boolean` | one of its ends is being moved (`reconnection()`) |
| `focusable` | `boolean` | it takes DOM focus (`keyboard()`) |
| `attributes` | `PartAttributes` | its attributes |

`UseEdgeResult<T>`:

| field | type | description |
| --- | --- | --- |
| `state` | `EdgeState<T>` | its state |
| `props` | `{ tabIndex } & DataAttributes` | its attributes and `tabIndex` |

## `useHandle`

`useHandle(options)` returns `UseHandleResult` for a handle rendered by hand: spread `props` on its
element, inside a node.

`UseHandleOptions`:

| option | type | default | description |
| --- | --- | --- | --- |
| `type` | `HandleType` | required | edges start (`"source"`) or end (`"target"`) here |
| `side` | `HandleSide` | required | the side of the node it sits on |
| `handleId` | `string` | none | its id among the node's handles of its type |
| `connectable` | `boolean` | `true` | a connection may start or end here |
| `connectableStart` | `boolean` | `true` | a connection may start here |
| `connectableEnd` | `boolean` | `true` | a connection may end here |
| `nodeId` | `string` | the enclosing `Flow.Node`'s | its node |

`state` is `HandleState` (see [`Flow.Handle`](/docs/api/primitives/handle)):

| field | type | description |
| --- | --- | --- |
| `nodeId` | `string` | its node |
| `handleId` | `string \| undefined` | its id |
| `type` | `HandleType` | its type |
| `side` | `HandleSide` | its side |
| `connectable` | `boolean` | a connection may start or end here: `data-connectable` |
| `connectableStart` | `boolean` | a connection may start here: `data-connectable-start` |
| `connectableEnd` | `boolean` | a connection may end here: `data-connectable-end` |
| `connecting` | `boolean` | the connection under way starts here: `data-connecting` |
| `valid` | `boolean` | the connection under way would end here, accepted: `data-valid` |
| `invalid` | `boolean` | the connection under way would end here, refused: `data-invalid` |
| `attributes` | `PartAttributes` | its attributes |

`UseHandleResult`:

| field | type | description |
| --- | --- | --- |
| `state` | `HandleState` | its state |
| `props` | `{ ref } & DataAttributes` | its attributes and the ref that registers it (its centre is measured) |

## Selecting hooks

The hooks below read one thing and change only when it does: a component built on them is not
rendered again when a node moves or the viewport pans, unless what it reads changed. The same
seven are in every adapter:

| React | Vue (composable) | Svelte (rune) | Angular (injection function) |
| --- | --- | --- | --- |
| `useFlowStore` | `useFlowStore`: a `ComputedRef` | `useFlowStore`: a `FlowValue` | `injectFlowStore`: a `Signal` |
| `useNodeId` | `useNodeId`: a `ComputedRef` | `useNodeId`: the id itself | `injectNodeId`: a `Signal` |
| `useNodesData` | `useNodesData`: a `ComputedRef` | `useNodesData`: a `FlowValue` | `injectNodesData`: a `Signal` |
| `useNodeConnections` | `useNodeConnections`: a `ComputedRef` | `useNodeConnections`: a `FlowValue` | `injectNodeConnections`: a `Signal` |
| `useInternalNode` | `useInternalNode`: a `ComputedRef` | `useInternalNode`: a `FlowValue` | `injectInternalNode`: a `Signal` |
| `useKeyPress` | `useKeyPress`: a read-only `Ref<boolean>` | `useKeyPress`: a `FlowValue<boolean>` | `injectKeyPress`: a `Signal<boolean>` |
| `useOnViewportChange` | `useOnViewportChange` | `useOnViewportChange` (`onstart`, `onchange`, `onend`) | `injectOnViewportChange` |

Their arguments follow each framework: in Vue a value, a ref or a getter (`() => props.nodeId`);
in Svelte a value or a getter; in Angular a value, a signal or a getter. A getter is read again
when what it reads changes, so the hook follows a prop.

## `useFlowStore`

`useFlowStore<S, T, F>(selector, equal?)` returns `selector({ model, engine })`, the model and the
engine of the root (`useFlow()`'s), and renders its component again only when the selected value
changed: `equal(previous, next)`, by default `Object.is`. The selector runs again on every change
of the model, on every view change of the engine (a measurement, the viewport, a gesture) and on
every render. Pass the registry and the features after the selected value's type
(`useFlowStore<number, Types, typeof features>(…)`).

<Framework name="react">

```tsx title="selected-count.tsx"
import { useFlowStore } from "@fragiola/flow-react";

export function SelectedCount() {
    const count = useFlowStore<number, Types, typeof features>(
        ({ model }) => model.get("selected-nodes").length,
    );
    return <output>{count} selected</output>;
}
```

</Framework>

<Framework name="vue">

```vue title="selected-count.vue"
<script setup lang="ts">
import { useFlowStore } from "@fragiola/flow-vue";

const count = useFlowStore<number, Types, typeof features>(
    ({ model }) => model.get("selected-nodes").length,
);
</script>

<template>
    <output>{{ count }} selected</output>
</template>
```

In Vue, it is a computed ref that triggers its readers only when the value changed; the selector
also runs again when a reactive value it reads changes.

</Framework>

<Framework name="svelte">

```svelte title="selected-count.svelte"
<script lang="ts">
    import { useFlowStore } from "@fragiola/flow-svelte";

    const count = useFlowStore<number, Types, typeof features>(
        ({ model }) => model.get("selected-nodes").length,
    );
</script>

<output>{count.current} selected</output>
```

In Svelte, it is a `FlowValue` whose `current` notifies only when the value changed.

</Framework>

<Framework name="angular">

```ts title="selected-count.ts"
import { Component } from "@angular/core";
import { injectFlowStore } from "@fragiola/flow-angular";

// rendered inside [flowRoot]
@Component({
    selector: "app-selected-count",
    template: `<output>{{ count() }} selected</output>`,
})
export class SelectedCount {
    protected readonly count = injectFlowStore<number, Types, typeof features>(
        ({ model }) => model.get("selected-nodes").length,
    );
}
```

In Angular, `injectFlowStore` gives the selector the model and the engine themselves (not
signals), and returns a signal that changes only when the value did; the selector also runs again
when a signal it reads changes.

</Framework>

A selector that builds an object or an array builds a new one at each change: give it an `equal`
that compares by value, `sameFlowValue` (from the package: arrays and plain records compared all
the way down), or it renders again every time.

```ts
const ids = useFlowStore(
    ({ model }) => model.get("selected-nodes").map((node) => node.id),
    sameFlowValue,
);
```

## `useNodeId`

`useNodeId()` returns the id of the node the component renders inside (`Flow.Node`), or `null`
outside one: a piece of a custom node (a badge, a menu, a handle of yours) reads its node without
being given its id.

<Framework name="react">

```tsx title="node-badge.tsx"

export function NodeBadge() {
    const nodeId = useNodeId();
```

</Framework>

<Framework name="vue">

```vue title="node-badge.vue"
const nodeId = useNodeId();
</script>

<template>
    <span class="text-xs opacity-60">{{ nodeId }}</span>
</template>
```

In Vue, it is a computed ref (the node a `Flow.Node` renders may change).

</Framework>

<Framework name="svelte">


In Svelte, it is the id itself, a `string | null`, read once in the component's script.

</Framework>

</Framework>

## `useNodesData` and `useNodeConnections`

`useNodesData<T>(nodeId)` returns a node's `NodeData<T>` (`{ id, type, data }`, the model's
`nodes-data-by`), or `null` while it does not exist. Given a list of ids,
`useNodesData<T>(nodeIds)` returns each existing node's, in the order given (an unknown id is
left out). It changes only when one of them changes its type or its data (compared by value), not
when a node moves or another node changes. `type` narrows `data`: check it before reading a
type's fields.

`useNodeConnections(options?)` returns the connections at a node, `NodeConnection[]` (the model's
`node-connections-by`): one per edge that starts or ends there, as its `edgeId`, `source`,
`sourceHandle`, `target` and `targetHandle`, in the document's order. It changes only when they do
(an edge added, removed or reconnected there), not when a node moves or an edge's data changes.
By default it reads the enclosing node; outside a node, give an `id` (without one it throws).

`UseNodeConnectionsOptions` (Angular: `InjectNodeConnectionsOptions`):

| option | type | default | description |
| --- | --- | --- | --- |
| `id` | `string` | the enclosing `Flow.Node`'s | the node |
| `handleId` | `string` | any | only the connections at this handle of it |
| `type` | `HandleType` | both | only those that end (`"target"`) or start (`"source"`) at it |

Together they make a node that follows its inputs: the sum of the nodes connected into it,
updated when an input's value changes or an edge is drawn or removed.

<Example id="connected-data" />

<Framework name="react">

```tsx title="sum-body.tsx"
import { useNodeConnections, useNodesData } from "@fragiola/flow-react";

/** Inside the sum node's Flow.Node: the values of the nodes connected into it. */
export function SumBody() {
    const connections = useNodeConnections({ type: "target" });
    const inputs = useNodesData<Types>(connections.map((connection) => connection.source));
    let total = 0;
    for (const input of inputs) if (input.type === "number") total += input.data.value;
    return <output>{total}</output>;
}
```

</Framework>

<Framework name="vue">

```vue title="sum-body.vue"
<script setup lang="ts">
import { useNodeConnections, useNodesData } from "@fragiola/flow-vue";
import { computed } from "vue";

// inside the sum node's Flow.Node: the values of the nodes connected into it
const connections = useNodeConnections({ type: "target" });
const inputs = useNodesData<Types>(() => connections.value.map((connection) => connection.source));
const total = computed(() => {
    let sum = 0;
    for (const input of inputs.value) if (input.type === "number") sum += input.data.value;
    return sum;
});
</script>

<template>
    <output>{{ total }}</output>
</template>
```

In Vue, both are computed refs; pass the ids as a getter (`() => …`) so the data follows the
connections.

</Framework>

<Framework name="svelte">

```svelte title="sum-body.svelte"
<script lang="ts">
    import { useNodeConnections, useNodesData } from "@fragiola/flow-svelte";

    // inside the sum node's Flow.Node: the values of the nodes connected into it
    const connections = useNodeConnections({ type: "target" });
    const inputs = useNodesData<Types>(() => connections.current.map((connection) => connection.source));
    const total = $derived(
        inputs.current.reduce((sum, input) => (input.type === "number" ? sum + input.data.value : sum), 0),
    );
</script>

<output>{total}</output>
```

In Svelte, both are `FlowValue`s; pass the ids as a getter so the data follows the connections.

</Framework>

<Framework name="angular">

```ts title="sum-body.ts"
import { Component, computed } from "@angular/core";
import { injectNodeConnections, injectNodesData } from "@fragiola/flow-angular";

// rendered inside the sum node's [flowNode] element
@Component({
    selector: "app-sum-body",
    template: `<output>{{ total() }}</output>`,
})
export class SumBody {
    private readonly connections = injectNodeConnections({ type: "target" });
    private readonly inputs = injectNodesData<Types>(() =>
        this.connections().map((connection) => connection.source),
    );
    protected readonly total = computed(() =>
        this.inputs().reduce((sum, input) => (input.type === "number" ? sum + input.data.value : sum), 0),
    );
}
```

In Angular, both are signals; pass the ids as a getter (or a signal) so the data follows the
connections.

</Framework>

## `useInternalNode`

`useInternalNode<T>(nodeId)` returns the node as the engine knows it on screen, an
`InternalNode<T>` (the engine's `internal-node-by`), or `undefined` while the node does not exist
or before the root is mounted. It changes only when one of its fields does (compared by value): a
pan or a zoom does not change it, a drag does.

| field | type | description |
| --- | --- | --- |
| `id` | `string` | its id |
| `node` | `FlowNode<T>` | the node, as the model holds it |
| `absolutePosition` | `XY` | its position in absolute flow coordinates (a child's added to its parents') |
| `rect` | `Rect` | its box in absolute flow coordinates, `nodeOrigin` applied (size 0 until measured) |
| `measured` | `boolean` | its size is known: measured, or given by the document |
| `zIndex` | `number` | its structural `z-index` |
| `handles` | `readonly FlowHandle[]` | its registered handles, with their centres and bounds (`handles-by`) |

<Framework name="react">

```tsx title="node-position.tsx"
import { useInternalNode } from "@fragiola/flow-react";

export function NodePosition({ nodeId }: { nodeId: string }) {
    const internal = useInternalNode(nodeId);
    if (!internal) return null;
    const { x, y } = internal.absolutePosition;
    return <output>{`${Math.round(x)}, ${Math.round(y)}`}</output>;
}
```

</Framework>

## `useKeyPress`

`useKeyPress(keys, options?)` returns whether a key, or a combo of keys, is held, and changes when
that does. `keys` is a combo or a list of combos (any of them):

- a combo is key names joined by `+`, all held at once: `"Shift"`, `"Meta+s"`,
  `"Control+Shift+z"` (other keys held too do not matter);
- a name is a `KeyboardEvent.key` (`"a"`, `"Shift"`, `"Delete"`, `" "` for Space) or a
  `KeyboardEvent.code` (`"KeyA"`, `"Space"`), compared without case;
- a list is any of its combos: `["Meta+z", "Control+z"]`.

The keys are read on `target`, by default the window of the root's element (its
`ownerDocument.defaultView`: the right one in an iframe or a pop-up window), never the global
`window`. Before the root is mounted, or outside a root with no `target`, it is `false`. The keys
held are forgotten when that window loses focus, and when Meta is released. It reads the keys
only: it prevents no default, and it does not tell a key typed in a field from another (check
`document.activeElement` yourself when that matters).

`UseKeyPressOptions` (Angular: `InjectKeyPressOptions`, whose `target` may be a signal):

| option | type | default | description |
| --- | --- | --- | --- |
| `target` | `KeyPressTarget \| null` | the root's window | where the keys are read: a window, a document or an element; `null`: nowhere |

<Framework name="react">

```tsx title="box-hint.tsx"
import { useKeyPress } from "@fragiola/flow-react";

export function BoxHint() {
    const held = useKeyPress("Shift");
    return held ? <p role="status">Drag on the canvas to draw a box</p> : null;
}
```

</Framework>

<Framework name="vue">

```vue title="box-hint.vue"
<script setup lang="ts">

const held = useKeyPress("Shift");
</script>

<template>
    <p v-if="held" role="status">Drag on the canvas to draw a box</p>
</template>
```

In Vue, it is a read-only `Ref<boolean>`; the keys and the options may be refs or getters.

</Framework>

<Framework name="svelte">


## `useOnViewportChange`

`useOnViewportChange(options)` calls back on the viewport's changes (the engine's
`viewport-change-start`, `viewport-change` and `viewport-change-end`) and renders nothing again:
save the view when it settles, hide a popover while the flow moves. `gesture` is `true` for a pan,
the wheel, a pinch or auto-pan, `false` for an action (`fit-view`, a control button). The latest
callbacks are called.

`UseOnViewportChangeOptions` (Svelte: lowercase `onstart`, `onchange`, `onend`; Angular:
`InjectOnViewportChangeOptions`):

| option | type | description |
| --- | --- | --- |
| `onStart` | `(viewport: Viewport, gesture: boolean) => void` | the viewport starts changing: a pan, a zoom, an animation |
| `onChange` | `(viewport: Viewport, gesture: boolean) => void` | each change of the viewport |
| `onEnd` | `(viewport: Viewport, gesture: boolean) => void` | the viewport stopped changing (a wheel's 150 ms after its last event) |

<Framework name="react">

```tsx title="save-view.tsx"
import { useOnViewportChange } from "@fragiola/flow-react";

export function SaveView({ onMoving }: { onMoving: (moving: boolean) => void }) {
    useOnViewportChange({
        onStart: () => onMoving(true),
        onEnd: (viewport) => {
            onMoving(false);
            localStorage.setItem("flow-view", JSON.stringify(viewport));
        },
    });
    return null;
}
```

</Framework>

<Framework name="vue">

```vue title="save-view.vue"
<script setup lang="ts">
import { useOnViewportChange } from "@fragiola/flow-vue";

const emit = defineEmits<{ moving: [moving: boolean] }>();

    onEnd: (viewport) => {
        emit("moving", false);
        localStorage.setItem("flow-view", JSON.stringify(viewport));
    },
});
</script>
```

In Vue, the options may be a value, a ref or a getter (`MaybeRefOrGetter`), and the callbacks are
read at each event (a reactive object's, a ref's or a getter's latest).

</Framework>

<Framework name="svelte">


In Svelte, the callbacks are lowercase, as a Svelte component's (`onstart`, `onchange`, `onend`);
the options may be a getter, read at each event.

</Framework>

<Framework name="angular">

```ts title="save-view.ts"

    readonly moving = output<boolean>();

    constructor() {

```

</Framework>

For every event of the engine, subscribe to it: `engine.subscribe(listener)`
([engine](/docs/api/engine)), or the root's callbacks.
