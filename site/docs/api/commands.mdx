The model runs 16 commands: the core's, and those of the features that bring some (each says which). Each one takes a JSON payload, checked against its JSON Schema, and returns a `CommandResult`: `{ ok: true, value }`, or `{ ok: false, error }`. Run one with `model.run(name, payload)` (typed by your registry and your features), or give it as untrusted JSON to `model.dispatch({ command, payload })`, which validates it first. `model.get("commands")` returns the same list for the commands of the installed features, with the schemas, ready to become tool definitions for an assistant.

Every command can return `invalid_payload` (the payload does not match its schema, or names a field of a feature that is not installed, with the path of each problem), `vetoed` (a middleware refused it), `queued` (a middleware ran it while another command was running) and `middleware_error`; a command of a feature that is not installed returns `not_found`, and an unknown name `unknown_command`. Each command lists the codes its own rules add: `not_found` (a node or edge it names is missing) and `refused` (a rule of the flow refuses the change: a permission flag, a duplicate edge, a parent cycle).

Positions are in flow coordinates (x grows to the right, y grows down); with sub-flows, a node's position is relative to its parent. The payload types below use `T`, your registry of node and edge types.

## Nodes

### `node.add`

Adds a node at the end of the drawing order: its type, position and data, optionally its id (generated when missing), size and flags. Refused when the id is taken.

| field | type | required | description |
| --- | --- | --- | --- |
| `id` | `string` | no | its id; generated when missing |
| `type` | `string` | yes | its type, from the app's registry |
| `position` | `object` | yes | its top-left corner, in flow coordinates (relative to its parent with sub-flows) |
| `data` | `object` | yes | the app's data, a JSON object typed by the node or edge type |
| `width` | `number` | no | its width, when the document gives one |
| `height` | `number` | no | its height, when the document gives one |
| `zIndex` | `number` | no | its place in the stacking order of its layer (nodes among nodes, edges among edges): a greater one is drawn above; default 0 |
| `draggable` | `boolean` | no | it may be moved (`node.move`); default true |
| `selectable` | `boolean` | no | it may be selected (`selection.set`); default true |
| `connectable` | `boolean` | no | edges may start or end at it (`edge.add`, `edge.reconnect`); default true |
| `deletable` | `boolean` | no | it may be removed (`node.remove`, `selection.remove`); default true |
| `hidden` | `boolean` | no | it is not shown; default false |
| `selected` | `boolean` | no | it is selected (requires the selection feature) |
| `parentId` | `string` | no | the node it lives in, its position relative to it (requires the subflows feature) |
| `extent` | `"parent" \| object` | no | "parent": it stays inside its parent's box; a rectangle (x, y, width, height): it stays inside it, in the coordinates of its position (requires the subflows feature) |
| `expandParent` | `boolean` | no | its parent grows to keep it inside (requires the subflows feature) |

**Result** (`{ nodeId: string }`)

It comes with the subflows feature: install `subflows()` from `@fragiola/flow/subflows` (without it, the command is `not_found`).

## Batches

### `batch`

Runs several commands as one atomic step: in order, all or nothing, with one event. The first failure is the batch's result, its path pointing into `commands`.

It may run as a step of a continuous gesture: `model.run(…, { transient: true })`.

**Payload** (`{ commands: BatchEntry<T>[] }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `commands` | `object[]` | yes | the commands, in order: each a `{ command, payload }` |

**Result** (`{ results: unknown[] }`)

| field | type | required | description |
| --- | --- | --- | --- |
| `results` | `JSON[]` | yes | each command's value, in order |

**Errors**: those of the commands it runs (the first failure, at its path in `commands`); nothing applies unless all succeed.

```ts
model.run("batch", {
    commands: [
        {
            command: "node.add",
            payload: {
                id: "a",
                type: "task",
                position: {
                    x: 0,
                    y: 0
                },
                data: {}
            }
        },
        {
            command: "node.add",
            payload: {
                id: "b",
                type: "task",
                position: {
                    x: 200,
                    y: 0
                },
                data: {}
            }
        },
        {
            command: "edge.add",
            payload: {
                source: "a",
                target: "b"
            }
        }
    ]
});
```

```json
{ "command": "batch", "payload": {"commands":[{"command":"node.add","payload":{"id":"a","type":"task","position":{"x":0,"y":0},"data":{}}},{"command":"node.add","payload":{"id":"b","type":"task","position":{"x":200,"y":0},"data":{}}},{"command":"edge.add","payload":{"source":"a","target":"b"}}]} }
```
