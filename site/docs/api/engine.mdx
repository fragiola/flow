The engine is one flow on screen. It owns the viewport and writes its transform to the viewport
element itself, measures nodes and handles with the root window's `ResizeObserver`, draws the
edges' paths, and runs every gesture (pan, pinch, drag, connect, reconnect, box select, resize,
the minimap) on Pointer Events with capture, plus the wheel and the keys. It changes the flow only
by running the model's commands, so every middleware sees what a gesture does. It never touches
the global `document` or `window`: everything goes through the root element.

`Flow.Root` creates and destroys it; in a React app you reach it with
[`useFlow`](/docs/api/primitives/hooks) or a [flow ref](/docs/api/primitives/flow-ref), and its
surface is the same five verbs as the model's:

<Framework name="react">

```tsx
import { useFlow } from "@fragiola/flow-react";

function ZoomReadout() {
    const { engine } = useFlow<Types, typeof features>();
    return (
        <button type="button" onClick={() => engine.run("fit-view", { padding: 0.2 })}>
            Fit
        </button>
    );
}
```

</Framework>

<Framework name="vue">

```vue title="zoom-readout.vue"
<script setup lang="ts">
import { useFlow } from "@fragiola/flow-vue";

const { engine } = useFlow<Types, typeof features>();
</script>

<template>
    <button type="button" @click="engine.run('fit-view', { padding: 0.2 })">Fit</button>
</template>
```

In Vue, `useFlow` is a composable of the same name: call it in `setup`, inside the root. The engine
is there from `setup` on; before the root has mounted, an action is refused and a read is empty.

</Framework>

<Framework name="svelte">

```svelte title="zoom-readout.svelte"
<script lang="ts">
    import { useFlow } from "@fragiola/flow-svelte";

    const flow = useFlow<Types, typeof features>();
</script>

<button type="button" onclick={() => flow.engine.run("fit-view", { padding: 0.2 })}>Fit</button>
```

In Svelte, `useFlow` is a rune of the same name: call it in a component's script, inside the
root. The root creates its engine in an `$effect`, once mounted: `flow.engine` is a getter that
follows it, and before the root has mounted (and on the server) an action is refused and a read
is empty.

</Framework>

<Framework name="angular">

```ts title="fit-button.ts"
import { Component } from "@angular/core";
import { injectFlow } from "@fragiola/flow-angular";

// rendered inside [flowRoot]
@Component({
    selector: "app-fit-button",
    template: `<button type="button" (click)="fit()">Fit</button>`,
})
export class FitButton {
    private readonly flow = injectFlow<Types, typeof features>();

    protected fit(): void {
        this.flow.engine.run("fit-view", { padding: 0.2 });
    }
}
```

In Angular, `useFlow` is `injectFlow`: call it in a field or a constructor of a component inside
the root. The root creates its engine after its first render (`afterNextRender`): `engine` is
there from the start and forwards to it, and before that an action is refused and a read is
empty.

</Framework>

## `createFlowEngine`

`createFlowEngine<T, F>(model, options?)` returns a `FlowEngine<T, F>`. Give it the root element
now (`root`) or attach it later (`engine.adapter.attachRoot`, what an adapter does); call
`destroy()` when the flow leaves the screen. A model may have several engines (two views of one
flow), each with its own viewport.

`FlowEngineOptions` (on `Flow.Root`, every one but `root` is a prop of the same name):

| option | type | default | description |
| --- | --- | --- | --- |
| `root` | `HTMLElement` | none | the root element; an adapter may attach it later |
| `defaultViewport` | `Viewport` | `{ x: 0, y: 0, zoom: 1 }` | the viewport it starts at |
| `minZoom` | `number` | `0.5` | the least zoom |
| `maxZoom` | `number` | `2` | the greatest zoom |
| `translateExtent` | `Rect` | none | the flow rectangle the view stays inside |
| `panOnDrag` | `boolean \| number[]` | `true` | a drag on the pane pans: `true` with the primary button (a touch, a pen), or the mouse buttons listed (`0` primary, `1` middle, `2` right; a middle or right pan that moved keeps the context menu out) |
| `panActivationKey` | `string \| null` | `" "` (Space) | held, a primary drag pans from anywhere, nodes included, and starts no other gesture (a `KeyboardEvent.key` or `.code`; not while typing in a field); `null` for none |
| `panOnScroll` | `boolean` | `false` | the wheel pans (Ctrl + wheel zooms); otherwise the wheel zooms |
| `panOnScrollMode` | `"free" \| "horizontal" \| "vertical"` | `"free"` | which way the wheel pans with `panOnScroll` (`PanOnScrollMode`) |
| `panOnScrollSpeed` | `number` | `1` | the factor of the wheel's pixels when it pans |
| `zoomActivationKey` | `string \| null` | `Meta` on Apple platforms, `Control` elsewhere | held, the wheel zooms while `panOnScroll` is on; `null` for none |
| `zoomOnScroll` | `boolean` | `true` | the wheel zooms around the pointer |
| `zoomOnPinch` | `boolean` | `true` | a two-finger pinch (and a trackpad's) zooms |
| `zoomOnDoubleClick` | `boolean` | `true` | a double click on the pane zooms in |
| `zoomStep` | `number` | `1.2` | the factor of `zoom-in` and `zoom-out` |
| `fitView` | `boolean \| FitViewPayload` | `false` | fits the nodes once every visible node is measured |
| `interactive` | `boolean` | `true` | whether gestures and keys may change the flow (pan and zoom stay) |
| `onlyRenderVisible` | `boolean` | `false` | adapters render only the nodes and edges in view |
| `pathOptions` | `PathOptions` | see [Path helpers](/docs/api/path-helpers) | the shape of the built-in edge paths |
| `autoPan` | `boolean \| AutoPanOptions` | `true` | the viewport pans while a node drag, a connection, a reconnection, a selection box or a resize has its pointer near the root's edge, and the gesture follows the pointer; `AutoPanOptions` `{ speed, margin, node, connect, selection, resize }`: the pixels a frame at the edge (default `10`), how near it starts (default `30` pixels), and each gesture's own switch (`{ connect: false }` keeps the view still while drawing an edge; each one left out pans; `AutoPanGesture` names them) |
| `paneClickDistance` | `number` | `3` | how far (in pixels) a press on the pane may move and still be a tap (a click: it clears the selection, `pane-click`); React Flow's is 0, ours stays 3 so a jittery click still counts |
| `nodeClickDistance` | `number` | `3` | how far a press on a node, an edge or a handle may move and still be a tap (it selects, `node-click`); with `connection({ clickToConnect })` a handle's drag starts only past it |
| `preventScrolling` | `boolean` | `true` | the wheel over the flow never scrolls the page, even when neither `zoomOnScroll` nor `panOnScroll` uses it; a `data-flow-no-wheel` element and the controls keep their wheel |
| `nodesFocusable` | `boolean` | `true` | nodes take DOM focus (with `keyboard()`); a node's own `focusable: false` still wins |
| `edgesFocusable` | `boolean` | `true` | edges take DOM focus (with `keyboard()`); an edge's own `focusable: false` still wins |
| `easing` | `(t: number) => number` | a smooth ease in and out | how an animated viewport action (`duration`) eases (`ViewportEasing`) |
| `nodeOrigin` | `XY` | `{ x: 0, y: 0 }` | the point of a node's box its `position` stands at, as shares of its size (`{ x: 0.5, y: 0.5 }`: its centre); every box the engine derives uses it (rects, handles, edge ends, bounds, `fit-view`, `visible-nodes`, the minimap, toolbars, the selection box, drag and resize); a child's position stays its box's top-left corner inside its parent's |
| `nodeExtent` | `Rect` | none | the flow rectangle every node's box stays inside when dragged, moved by the arrows or resized |
| `elevateNodesOnSelect` | `boolean` | `true` | a selected node, and its descendants with it, is drawn above the other nodes (`node-z-index-by`) |
| `elevateEdgesOnSelect` | `boolean` | `false` | a selected edge is drawn above the other edges (`drawn-edges`) |

The roots of the four adapters take every option but `root` as a prop of the same name (Vue:
kebab-case in a template; Angular: an input of `flowRoot`) and send a change through
`engine.adapter.setOptions` ([Root](/docs/api/primitives/root#props)).

## The members

| member | does |
| --- | --- |
| `run(action, payload?)` | runs a screen action; returns a `CommandResult` (refused, never thrown) |
| `can(action, payload?)` | whether `run` would succeed now (a Controls button's disabled state is `!engine.can("zoom-in")`) |
| `check(action, payload?)` | what `run` would return, without doing it |
| `get(key, payload?)` | reads a fact of the flow on screen |
| `is(key, payload?)` | asks a yes/no question about it |
| `subscribe(listener)` | listens to the engine's events; returns its remover |
| `destroy()` | releases every listener and element; nothing runs afterwards |
| `adapter` | what only an adapter calls (below) |

An action's key never has a dot (`fit-view`), a command's always does (`node.move`): commands
change the document through the model, actions do what only the screen can. The installed
features add keys: `EngineActionKeyOf<F>`, `EngineGetKeyOf<F>` and `EngineIsKeyOf<F>` are those of
an engine whose model has the features `F`. `EngineActionMap`, `EngineGetMap<T>` and `EngineIsMap`
map each key to its payload and result; `EngineActionKey`, `EngineActionPayload<K>`,
`EngineActionResult<K>`, `EngineGetKey`, `EngineGetPayload<K>`, `EngineGetResult<T, K>`,
`EngineIsKey` and `EngineIsPayload<K>` read them.

## Actions

`around` and the selection box are root-relative pixels; `screen-to-flow` and `flow-to-screen`
take and give client points (a pointer's `clientX` / `clientY`, a drop's).

| action | payload | does |
| --- | --- | --- |
| `"set-viewport"` | `{ x?, y?, zoom?, duration? }` | sets the viewport (what it leaves out stays), zoom limits and extent kept |
| `"pan-by"` | `{ x, y }` | pans by a screen offset, in pixels |
| `"zoom-in"` | `ZoomStepPayload` | zooms in by a step around a point; refused at the greatest zoom |
| `"zoom-out"` | `ZoomStepPayload` | zooms out by a step; refused at the least zoom |
| `"zoom-to"` | `{ zoom, around?, duration? }` | zooms to a level around a point (default the root's centre) |
| `"fit-view"` | `FitViewPayload` | fits the nodes (or some) in the root; refused while none is measured or the root has no size |
| `"center-on"` | `{ x, y, zoom?, duration? }` | centres a flow point in the root |
| `"focus-node"` | `{ nodeId }` | gives DOM focus to a node's element, panning it into view |
| `"set-interactive"` | `InteractivityPayload` | lets gestures and keys change the flow, or not: all of them (`interactive`) or one kind (`drag`, `connect`, `select`, `reconnect`), the switches left out kept (`Flow.ToggleInteractive` switches `drag`, `connect` and `select`); pan and zoom stay; a switch turned off cancels the gesture under way; returns every switch (`Interactivity`) |
| `"cancel-gesture"` | none | cancels the gesture under way (what Escape does) and stops a viewport animation where it is; refused when there is neither |

`duration` (milliseconds, default `0`: at once) animates `set-viewport`, `zoom-in`, `zoom-out`,
`zoom-to`, `fit-view` and `center-on` on the root window's frames, eased by the `easing` option:
the result is the viewport it ends at (zoom limits and extent kept), and every frame tells a
`viewport-change` with `gesture: false`. Another viewport action, a pan, the wheel, a pinch,
`cancel-gesture` or `destroy` stops it where it is.

`InteractivityPayload` is a part of `Interactivity`, the switches (at least one given; a missing
one stays as it is):

| switch | stops (when false) |
| --- | --- |
| `interactive` | every gesture and key that changes the flow (each kind below, a resize, a delete key) |
| `drag` | dragging nodes, and moving them with the arrows (`drag()`, `keyboard()`) |
| `connect` | drawing edges from handles: a drag, a tap (click-to-connect), Enter on a handle (whose `tabindex` goes) |
| `select` | a tap's selection, the selection box, Enter and Space; a drag no longer selects the node it drags |
| `reconnect` | moving an edge's ends (`reconnection()`); `connect: false` stops it too (moving an end connects it anew) |

`InteractionKind` names the four kinds. The switches are the engine's state, read by every
feature at the moment it would act: no feature is installed again.

`FitViewPayload` (also the `fitView` option's object form):

| field | type | description |
| --- | --- | --- |
| `padding` | `FitPadding` | the room kept free on every side: a number is a share of the root's size, a `"<n>px"` string pixels, `{ top, right, bottom, left }` each side's (a side left out keeps none); default `0.1` |
| `nodeIds` | `string[]` | only these nodes; default every node that is not hidden |
| `includeHidden` | `boolean` | without `nodeIds`, the hidden nodes of known size too; default `false` |
| `minZoom` | `number` | the least zoom it may pick, within the engine's limits (it narrows them, never widens) |
| `maxZoom` | `number` | the greatest zoom it may pick, within the engine's limits |
| `duration` | `number` | how long it animates, in milliseconds; default `0`: at once |

`ZoomStepPayload`:

| field | type | description |
| --- | --- | --- |
| `step` | `number` | the factor; default the engine's `zoomStep` |
| `around` | `XY` | the root-relative point that stays put; default the root's centre |
| `duration` | `number` | how long it animates, in milliseconds; default `0`: at once |

## Reads

| key | payload | returns |
| --- | --- | --- |
| `"viewport"` | none | the `Viewport` |
| `"root-size"` | none | the root's `{ width, height }`, in pixels |
| `"edge-path-by"` | `{ edgeId }` | its `EdgePath` (path, label point, ends and sides), undefined until both nodes have a size; an app type gets the bezier |
| `"node-rect-by"` | `{ nodeId }` | its absolute box (size 0 until measured or given) |
| `"nodes-bounds"` | `{ nodeIds? }` | the box of the nodes (or some); none without a node |
| `"intersecting-nodes"` | `IntersectingNodesPayload` | the nodes whose box (measured or given) shares some area with a node's box or a flow rectangle (`partial: false`: lies wholly inside it), in the document's order; hidden nodes, nodes of unknown size and the node itself are left out |
| `"viewport-for-bounds"` | `ViewportForBoundsPayload` | the viewport that frames a flow rectangle in the root, as `fit-view` would set it (padding, zoom limits and translate extent kept); undefined while the root has no size |
| `"screen-to-flow"` | `XY` | a client point as a flow point (a drop's position) |
| `"flow-to-screen"` | `XY` | a flow point as a client point |
| `"visible-nodes"` | none | the nodes in view, plus those not measured yet |
| `"visible-edges"` | none | the edges whose ends' box is in view |
| `"drawn-edges"` | none | the edges to draw, in drawing order: those shown whose nodes are measured (with `onlyRenderVisible`, those in view), by `zIndex` (a selected one raised with `elevateEdgesOnSelect`), the document's order among equals |
| `"node-z-index-by"` | `{ nodeId }` | a node's structural `z-index` among the nodes: its `zIndex` (a selected node and its descendants raised with `elevateNodesOnSelect`), always above its parent's |
| `"handles-by"` | `{ nodeId }` | a node's registered handles (`FlowHandle[]`), with their centres |
| `"background-pattern"` | `BackgroundPatternPayload` | one tile of a background pattern at the current viewport |
| `"node-toolbar-by"` | `NodeToolbarPayload` | where a node's toolbar goes, outside the zoom: beside a node, or beside several nodes' bounds (`nodeIds`); undefined until one of them has a size |
| `"edge-toolbar-by"` | `EdgeToolbarPayload` | where an edge's toolbar goes, outside the zoom (an `EdgeToolbarPosition`): at its label point, one of its ends or a flow point; undefined until the edge is drawn |
| `"selection-box"` | none | the box being drawn (a root-relative `SelectionBox`), or null (`selection()`; `undefined` without it) |
| `"dragging-node-ids"` | none | the nodes being dragged (`drag()`) |
| `"connection"` | none | the `Connection` being drawn, or null (`connection()`; `undefined` without it) |
| `"minimap-view"` | `{ width, height }` | what a minimap of that many pixels draws (`minimap()`) |
| `"minimap-point-to-flow"` | `{ client }` | a client point on the minimap (the one under it, else the first) as a flow point, for a click on it; undefined while no minimap has a size (`minimap()`) |

`IntersectingNodesPayload`:

| field | type | description |
| --- | --- | --- |
| `nodeId` | `string` | the node whose box the others are compared with (it is left out); wins over `rect` |
| `rect` | `Rect` | a rectangle in absolute flow coordinates, without `nodeId` |
| `partial` | `boolean` | any shared area counts (default `true`); `false`: only a node wholly inside |

`ViewportForBoundsPayload`:

| field | type | description |
| --- | --- | --- |
| `bounds` | `Rect` | the flow rectangle to frame |
| `padding` | `FitPadding` | the room kept free on every side, or each side's, as `fit-view`'s; default 0.1 |
| `minZoom` | `number` | the least zoom it may pick (within the engine's limits); default the engine's `minZoom` |
| `maxZoom` | `number` | the greatest zoom it may pick (within the engine's limits); default the engine's `maxZoom` |

The same framing is a pure function, `viewportForBounds(bounds, width, height, options?)`: the
viewport that shows `bounds` whole and centred in a root of `width` × `height` pixels (a server
render, a thumbnail, a saved view), with no engine. Its `ViewportForBoundsOptions`:

| option | type | description |
| --- | --- | --- |
| `padding` | `FitPadding` | the room kept free on every side, or each side's (the bounds centred in what is left); default 0.1 |
| `minZoom` | `number` | the least zoom it may pick; default 0.5 |

`FitPadding` is a `PaddingValue` for every side, or `{ top?, right?, bottom?, left? }` of them; a
`PaddingValue` is a number (a share of the root's width for the left and right, of its height for
the top and bottom) or a `` `${number}px` `` string (pixels). A plain number frames exactly as
before per-side padding existed.
| `maxZoom` | `number` | the greatest zoom it may pick; default 2 |

`BackgroundPatternPayload`:

| field | type | description |
| --- | --- | --- |
| `variant` | `BackgroundVariant` | `"dots"` (default), `"lines"` or `"cross"` |
| `gap` | `number \| [number, number]` | the distance between two marks, in flow units; default 20 |
| `size` | `number` | `dots`: a dot's diameter, in flow units, default 1; `lines`: the stroke width in screen pixels (not scaled by the zoom), default 1; `cross`: each bar's length (an arm is half of it), in flow units, default 6 |
| `offset` | `number \| [number, number]` | the pattern's shift from the flow's origin, in flow units; default 0 |

`BackgroundPattern`, one tile for an SVG `pattern` with `patternUnits="userSpaceOnUse"`:

| field | type | description |
| --- | --- | --- |
| `variant` | `BackgroundVariant` | the marks |
| `x` | `number` | the tile's left, on the screen |
| `y` | `number` | the tile's top |
| `width` | `number` | the tile's width, in pixels |
| `height` | `number` | the tile's height |
| `dot` | `{ cx, cy, r } \| undefined` | the dot, for `dots` |
| `path` | `string \| undefined` | the lines' or the cross's path data |
| `strokeWidth` | `number` | the stroke width of `path`, in pixels |

`NodeToolbarPayload`:

| field | type | description |
| --- | --- | --- |
| `nodeId` | `string` | the node it stands beside (without `nodeIds`) |
| `nodeIds` | `string[]` | the nodes whose bounds it stands beside (their measured boxes); wins over `nodeId` when not empty |
| `side` | `HandleSide` | the side it stands on; default `"top"` |
| `align` | `"start" \| "center" \| "end"` | where along that side; default `"center"` |
| `offset` | `number` | the gap to the node, in pixels; default 10 |

`NodeToolbarPosition`, a root-relative anchor outside the zoom:

| field | type | description |
| --- | --- | --- |
| `x` | `number` | the anchor's left, in pixels |
| `y` | `number` | the anchor's top |
| `anchorX` | `number` | which point of the toolbar goes there, as a share of its width (`0.5`: its centre) |
| `anchorY` | `number` | the same along its height (`1`: its bottom) |

`EdgeToolbarPayload`:

| field | type | description |
| --- | --- | --- |
| `edgeId` | `string` | the edge |
| `position` | `"label" \| "source" \| "target"` | the point of the edge it stands at: its label point (default) or one of its ends |
| `point` | `XY` | a flow point it stands at instead (absolute flow coordinates); wins over `position` |
| `offset` | `XY` | a screen offset from that point, in pixels; default `{ x: 0, y: 0 }` |
| `alignX` | `"start" \| "center" \| "end"` | which of the toolbar's edges goes at the point across: its left, its centre (default) or its right |
| `alignY` | `"start" \| "center" \| "end"` | the same down: its top, its centre (default) or its bottom |

`EdgeToolbarPosition` is a `NodeToolbarPosition` whose `anchorX` and `anchorY` follow `alignX` and
`alignY` (`0`, `0.5` or `1`; `0.5` by default: the toolbar's centre goes to the point). The `toolbar` part's attributes take `{ edgeId }` for an
edge's toolbar (its `data-flow-id`), `{ nodeId }` for a node's, nothing for several nodes'.

`Connection`, the connection being drawn:

| field | type | description |
| --- | --- | --- |
| `from` | `FlowHandle` | the handle it started from |
| `fromPoint` | `XY` | where it starts, in flow coordinates (the handle's centre) |
| `toPoint` | `XY` | the pointer, or the centre of the handle it snapped to |
| `toSide` | `HandleSide` | the side it enters by |
| `to` | `FlowHandle \| undefined` | the handle within the radius it would end at |
| `status` | `"valid" \| "invalid" \| null` | `valid`: the drop adds an edge; `invalid`: `model.can` refuses it; null: no handle near |
| `path` | `string` | the connection line's path, as `connection({ lineType })` draws it (a bezier by default) |
| `reconnecting` | `{ edgeId, end } \| undefined` | the edge whose end is moved (`reconnection()`) |

| field | type | description |
| --- | --- | --- |
| `viewBox` | `Rect` | the SVG `viewBox`: the nodes and the view, fitted to the minimap's aspect |
| `viewBoxAttribute` | `string` | `viewBox` as the attribute writes it |
| `scale` | `number` | the flow units one minimap pixel stands for |
| `nodes` | `{ nodeId, x, y, width, height }[]` | the box of every node shown (not hidden) and measured, in view or not |
| `view` | `Rect` | what the root shows |
| `maskPath` | `string` | the view box with the view cut out, for `fill-rule="evenodd"` |

| --- | --- | --- |
| `"interactive"` | none | gestures and keys may change the flow |

| `"box-selecting"` | none | a box selection is being drawn (`selection()`) |
| `"dragging"` | none | nodes are being dragged (`drag()`) |
| `"node-dragging"` | `{ nodeId }` | this node is being dragged (`drag()`) |
| `"resizing"` | none | a node is being resized (`resize()`) |
| `"node-resizing"` | `{ nodeId }` | this node is being resized (`resize()`) |
| `"connecting"` | none | a connection is being drawn (`connection()`) |
| `"edge-reconnecting"` | `{ edgeId }` | one of its ends is being moved (`reconnection()`) |
| `"node-focusable"` | `{ nodeId }` | it takes DOM focus, `tabindex="0"` (`keyboard()`): shown, its `focusable` not false, `nodesFocusable` on |
| `"edge-focusable"` | `{ edgeId }` | it takes DOM focus (`keyboard()`): shown, its `focusable` not false, `edgesFocusable` on |

## Events

`engine.subscribe(listener)` hears what happens on screen, a `FlowEngineEvent` (its `type` is a
`FlowEngineEventType`). No text is built in: turn an event into your own words for your own live
region (see [Accessible names](/docs/getting-started/accessible-names)), or sync a controlled
viewport from it.

| event | fields | when |
| --- | --- | --- |
| `"viewport-change"` | `viewport`, `gesture` | the viewport changed; `gesture`: by a pan, a zoom or a pinch, not an action |
| `"viewport-change-start"` | `viewport`, `gesture` | the viewport starts a move: the first change of a pan, a wheel, a pinch, an animation or an action (`viewport` is where it starts) |
| `"viewport-change-end"` | `viewport`, `gesture` | the move ended: the pan or pinch released, the animation done or stopped, the wheel at rest for 150 ms; an action that does not animate starts and ends at once |
| `"ready"` | none | the root has a size and every shown node was measured, once per engine |
| `"node-click"`, `"edge-click"`, `"pane-click"` | `nodeId` / `edgeId`, `point`, `client`, `event` | a tap: a primary press released within the tap distance (`paneClickDistance`, `nodeClickDistance`) that started no gesture; a press that dragged or panned is none. Told after the selection changed, and while the flow is not interactive too |
| `"node-double-click"`, `"edge-double-click"`, `"pane-double-click"` | the same | a double click whose two presses were taps; on the pane it also zooms in (`zoomOnDoubleClick`) |
| `"node-context-menu"`, `"edge-context-menu"`, `"pane-context-menu"` | the same | a context menu (a right click, the menu key); the app calls `event.preventDefault()` to show its own. One a right-button pan keeps out is none |
| `"selection-context-menu"` | `nodeIds`, `edgeIds`, `point`, `client`, `event` | a context menu on a selected node while several nodes are selected (instead of `node-context-menu`) |
| `"drag-start"` | `nodeIds` | a drag of these nodes started (`drag()`) |
| `"nodes-move"` | `nodeIds`, `source` | nodes were dropped after a drag, or moved by the arrows; `source` is a `MoveSource`, `"pointer"` or `"keyboard"` |
| `"drag-cancel"` | `nodeIds` | a drag was cancelled: its nodes went back |
| `"connect-start"` | `nodeId`, `handleId`, `handleType`, `input` | a connection started from a handle (`connection()`); `input` (a `MoveSource`): `"pointer"` (a drag or a tap) or `"keyboard"` (Enter on a focused handle, with `keyboard()`) |
| `"connect-target"` | `nodeId`, `handleId`, `handleType`, `index`, `count` | a keyboard connection points at another target: the `index`-th of the `count` handles the model accepts, nearest first (`index` -1 and no handle when it accepts none), for your live region |
| `"connect"` | `edgeId`, `source`, `target`, `input` | a connection was dropped on a handle (or Enter chose it): an edge was added |
| `"connect-cancel"` | `refused`, `input`, `dropped`, `from`, `to`, `client`, `point` | a connection ended without an edge; `refused`: on a handle `model.can("edge.add")` refused; `dropped`: released (or confirmed), not cancelled by Escape, the lock or a `pointercancel`; where it ended (`ConnectionDrop`) |
| `"reconnect-start"` | `edgeId`, `end` | an edge's end was grabbed (`reconnection()`) |
| `"reconnect"` | `edgeId`, `source`, `target` | an edge was reconnected |
| `"reconnect-cancel"` | `edgeId`, `end`, `refused`, `dropped`, `from`, `to`, `client`, `point` | a reconnection ended with the edge as it was (`dropped` as for `connect-cancel`); `from` is the edge's fixed end |
| `"resize-start"` | `nodeId`, `width`, `height` | a resize started (`resize()`), at the node's size then; its steps are `node.resize` commands run as `transient` (`model.subscribe`, `onNodesChange`) |
| `"resize-cancel"` | `nodeId` | a resize was cancelled: the node is back at its size |
| `"resize"` | `nodeId`, `width`, `height`, `source` | a node was resized (`resize()`): by a drag (`source: "pointer"`), or by the arrows on a focused resize handle (`"keyboard"`, with `keyboard()`) |
| `"box-select-start"` | `client`, `point` | a selection box started (`selection()`): where, as a client and a flow point |
| `"box-select"` | `nodeIds`, `edgeIds` | a box selection ended with these selected (`selection()`) |
| `"remove"` | `nodeIds`, `edgeIds` | a delete key (`deleteKeys`: Delete or Backspace by default) removed these (`keyboard()`), after its `beforeDelete` |

`ConnectionDrop`, where a connection or a reconnection ended without an edge:

| field | type | description |
| --- | --- | --- |
| `from` | `ConnectionEnd` | the handle it came from (a reconnection: the edge's fixed end), `{ nodeId, handleId, type }` |
| `to` | `ConnectionEnd \| undefined` | the handle it was over, none over nothing |
| `client` | `XY` | the drop as a client point (`clientX`, `clientY`): where a node made from it goes on screen |
| `point` | `XY` | the drop as a flow point (`screen-to-flow` of `client`); a keyboard connection's is its target's centre (or its start's) |

`FlowPointerInfo` (`point`, `client`, `event`) is what the tap, double-click and context-menu
events share; `FlowEngineEventOf<K>` is the event of one type. `ENGINE_EVENT_CALLBACKS` maps each
event but `viewport-change` (a `CallbackEventType`) to the name of its root callback in every
adapter (an `EventCallbackName`: `NodeClick` is React's `onNodeClick`, Vue's `nodeClick` (`@node-click`),
Svelte's `onnodeclick`, Angular's `(nodeClick)`; see [Root](/docs/api/primitives/root#props)).

The engine tells taps from its own gestures: the pointer is captured on the root at every press,
so a browser's `click` and `dblclick` target the root. A click that ended a drag or a pan is
never a tap.

```ts
const stop = engine.subscribe((event) => {
    if (event.type === "connect") announce(`Connected ${event.source} to ${event.target}.`);
    if (event.type === "connect-cancel" && event.refused) announce("That connection is not allowed.");
});
```

## The adapter contract

`engine.adapter` is a `FlowEngineAdapter`: what a framework adapter (`@fragiola/flow-react`,
`@fragiola/flow-vue`, `@fragiola/flow-svelte`, `@fragiola/flow-angular`) calls. An app never needs it. The adapter renders and
attaches; the engine listens to the root itself and resolves every press, key and wheel from the
part attributes, so every adapter behaves the same.

| member | does |
| --- | --- |
| `model` | the model this engine draws |
| `settings` | the rendering settings from the options: `onlyRenderVisible` |
| `setOptions(options)` | options changed (a root prop): they apply from now on, a gesture under way included; `root`, `defaultViewport` and `fitView` are creation options |
| `attachRoot(element)` | attaches the root: the engine listens to its pointer, wheel, key and focus events and sets its `touch-action: none` |
| `detachRoot()` | detaches it, cancelling a gesture under way |
| `attachViewport(element)` | attaches (or, with `null`, detaches) the viewport element: the engine writes its `transform` and `transform-origin`, the framework never does |
| `registerNode(nodeId, element)` | registers (or unregisters) a node's element: the engine measures it |
| `registerHandle(handle, element)` | registers (or unregisters) a handle: the engine measures its centre relative to its node |
| `setPartOptions(part, id, options)` | options a part's primitive takes (a resizer's `minWidth`, …); `null` drops them |
| `attributes(part, payload?)` | the record to spread on a part: `data-flow-part`, `data-flow-id` and its state |
| `subscribe(listener)` | the view changed (a `ViewChange`); returns its remover |
| `getSnapshot()` | a number that changes whenever the view changes |

`HandleRegistration`, what a handle registers:

| field | type | description |
| --- | --- | --- |
| `nodeId` | `string` | the node it belongs to |
| `handleId` | `string` | its id among the node's handles of its type; none: the default handle |
| `type` | `HandleType` | `"source"` or `"target"` |
| `side` | `HandleSide` | the side it sits on: the direction its edges leave or enter by |
| `connectable` | `boolean` | a connection may start or end at it; default true |
| `connectableStart` | `boolean` | a connection may start at it (a drag, a tap, a key); default true |
| `connectableEnd` | `boolean` | a connection may end at it (be its target); default true |

`FlowHandle`, a registered handle (`handles-by`, a connection's ends):

| field | type | description |
| --- | --- | --- |
| `nodeId` | `string` | its node |
| `handleId` | `string \| undefined` | its id |
| `type` | `HandleType` | source or target |
| `side` | `HandleSide` | its side |
| `connectable` | `boolean` | its flag and its node's |
| `connectableStart` | `boolean` | it may start a connection (and is connectable) |
| `connectableEnd` | `boolean` | it may end one (and is connectable) |
| `center` | `XY \| undefined` | its centre in absolute flow coordinates, once measured |
| `bounds` | `Rect \| undefined` | its box relative to its node, in flow units, once measured |

`ViewChange`, what changed in the view, so an adapter re-renders only what depends on it:

| field | type | description |
| --- | --- | --- |
| `viewport` | `boolean` | the viewport moved or zoomed (the background, the minimap, toolbars) |
| `measured` | `boolean` | a node or handle was measured (edges, the minimap, toolbars) |
| `gesture` | `boolean` | a gesture's state changed (the connection line, the selection box, state attributes) |

`PartPayloadMap` types the payload of each part's `attributes` (`node` takes `{ nodeId }`,
`handle` a `HandleRegistration`, `reconnect-anchor` `{ edgeId, end }`, …). `PressTarget` is what
the engine resolved a press to (`kind`: `pane`, `node`, `edge`, `handle`, `resize-handle`,
`minimap` or `other`, with the ids; `outsideDragHandle` on a press on a node that holds a drag
handle, outside it), handed to the features' hooks.

## Part attributes

The attribute names are constants, and the helpers give the static attributes without an engine
(a server render, a part with no state):

| export | value |
| --- | --- |
| `PART_ATTRIBUTE` | `"data-flow-part"`: every element's part name (`FlowPart`: `root`, `node`, `edge`, `handle`, …) |
| `ID_ATTRIBUTE` | `"data-flow-id"`: the id of the node, edge or handle a part stands for |
| `POSITION_ATTRIBUTE` | `"data-position"`: a resize handle's corner or side |
| `END_ATTRIBUTE` | `"data-end"`: a reconnect anchor's end of its edge |
| `NO_GESTURE_ATTRIBUTE` | `"data-flow-no-gesture"`: a subtree inside a node that starts no gesture (a slider, a field) |
| `NO_WHEEL_ATTRIBUTE` | `"data-flow-no-wheel"`: a subtree where the wheel scrolls its content instead of zooming |
| `DRAG_HANDLE_ATTRIBUTE` | `"data-flow-drag-handle"`: an element inside a node that is its drag handle; a node holding one drags only from it (a press elsewhere on it still selects it) |
| `partAttributes(part, id?)` | `{ "data-flow-part": part, "data-flow-id": id }` |
| `flag(on)` | a boolean state attribute's value: `""` when on, `undefined` when off |

`PartAttributes` is a read-only record of them, `MutablePartAttributes` the writable one the engine
and its features fill. The state attributes each part carries: [State
attributes](/docs/concepts/state-attributes).
